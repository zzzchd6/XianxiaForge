# 文风与领域知识蒸馏 · 验收文档（创作库扩展）

> 二期扩展：在不改动原剧情素材 ETL 的前提下，新增「作者文风蒸馏」与「专业领域知识蒸馏」
> 两个独立功能。本文档供部署、验收、回滚使用。

---

## 一、功能概述

| 功能 | 脚本 | 目标表 | 能力 |
|------|------|--------|------|
| 作者文风蒸馏 | `distill_style.py` | `style_preset` | 输入同一作者/风格的多本 TXT，块级抽取 6 大风格维度→全局聚合成 1 套结构化文风配置，供 Novel Studio 文风档位直接读用 |
| 专业领域知识蒸馏 | `extract_domain_knowledge.py` | `plot_domain_knowledge` | 输入专业书籍 TXT，抽取 5 类领域知识（术语/规则/误区/表达/案例），向量化入库，供 RAG 检索注入写作上下文 |

**与原系统的关系**：两脚本均 `import extract_materials as em`，100% 复用其读取/清洗/切块/LLM 调用/重试/JSON 校验/向量化/去重/连接/日志/配置体系;**未改动 `extract_materials.py` 一行**;所有新增表建在创作库 `novel_studio`,**诛仙原著库只读、零写入**。

**核心设计对齐**：
- `style_preset` 列名 1:1 对齐诛仙库 `style_global_config`(6 维度同名),仅 `book_id→project_id`,Node 文风引擎可 drop-in 读取。
- `plot_domain_knowledge` 字段规范对齐 4 张剧情素材表;采用「单表 + `knowledge_type` 五枚举」便于跨类 RAG 召回。
- 向量统一 bge-small-zh-v1.5 / 512 维 / 归一化 cosine,与全库同源。

## 三、使用手册（CLI）

### 3.1 文风蒸馏

```bash
python distill_style.py <TXT或目录> --preset-name <名> [选项]
```

| 参数 | 说明 |
|------|------|
| `path` | 同一作者/风格的 TXT 文件或目录（目录=多本合并蒸馏一套风格） |
| `--preset-name`（必填） | 文风预设名，幂等键 |
| `--author` | 作者名 |
| `--project-id` | 归属项目；默认取 `TARGET_PROJECT_ID`（空=全局共享 NULL） |
| `--no-local-stats` | 关闭本地量化统计 |
| `--no-reduce` | 关闭 LLM 归纳凝练（省一次调用） |
| `--dry-run` / `--dump FILE` / `--max-chunks N` | 只蒸馏不入库 / 导出 JSON / 只取前 N 块 |

```bash
# 验证：前 30 块，不入库，导出核对
python distill_style.py "sucaitest/《凡人修仙传》...txt" --preset-name "忘语·凡人流" --author 忘语 --dry-run --max-chunks 30 --dump style_check.json
# 正式：多本同作者合并入库
python distill_style.py "K:\忘语作品集\" --preset-name "忘语·凡人流" --author 忘语
```

### 3.2 领域知识蒸馏

```bash
python extract_domain_knowledge.py <TXT或目录> [--domain 领域] [--source-book 书名] [选项]
```

| 参数 | 说明 |
|------|------|
| `path` | 专业书籍 TXT 文件或目录 |
| `--domain` | 领域归属(中医/刑侦/军事…),RAG 过滤召回用 |
| `--source-book` | 来源书名(默认取文件名) |
| `--project-id` / `--dry-run` / `--dump` / `--max-chunks` | 同上 |

```bash
python extract_domain_knowledge.py "K:\专业书\法医学.txt" --domain 刑侦 --dry-run --max-chunks 20 --dump kn.json
python extract_domain_knowledge.py "K:\专业书\中医基础.txt" --domain 中医
```

## 四、验收测试用例

| # | 用例 | 操作步骤 | 预期结果 | 通过标准 |
|---|------|----------|----------|----------|
| 1 | 建表幂等 | 连续执行两个 DDL 各 2 次 | 首次建表,再次无报错、无重复 | 两表存在;重复执行不报错 |
| 2 | 文风 dry-run | `distill_style.py <单本> --preset-name t --dry-run --max-chunks 20` | 打印 6 维终稿+置信度,**不入库** | `style_preset` 计数不变;日志有聚合结果 |
| 3 | 文风正式入库+幂等 | 去掉 --dry-run 跑一次,再跑一次 | 首次 insert,二次 update 且 `version` 递增 | 同名预设始终 1 行;version 从 1→2 |
| 4 | 领域知识正式入库 | `extract_domain_knowledge.py <书> --domain 刑侦` | 抽取→去重→入库,分类分布日志 | 表新增记录;`knowledge_type` 均在 5 枚举内;`quality_score`≥门槛 |
| 5 | 字段边界 | 抽查入库记录 | content 长度≤300;source_snippet≤120;embedding 为 512 维 | 无超长;向量维度=512 |
| 6 | **诛仙库零变更(边界铁律)** | 蒸馏前后对比诛仙库(见下 SQL) | `style_global_config`/`style_scene_mapping`/`novel_*` 行数、结构完全不变 | **诛仙库任意表无新增行、无结构改动** |
| 7 | 容错不中断 | 断网或错误 key 跑领域知识 | 单块重试后跳过,记 `etl_failures.log`,整批不崩 | 进程正常结束;失败落日志 |

**用例 6 边界校验 SQL**（在诛仙库所在连接执行；本工具全程不连诛仙库，此为独立核验）：
```sql
-- 蒸馏前后各跑一次，比对行数应完全一致
SELECT 'style_global_config' t, count(*) FROM style_global_config
UNION ALL SELECT 'style_scene_mapping', count(*) FROM style_scene_mapping
UNION ALL SELECT 'novel_book', count(*) FROM novel_book;
```

**结果验证 SQL**（创作库）：
```sql
SELECT style_name, author, quality_score, confidence, sample_word_count,
       array_length(mental_models,1) AS n_mind, array_length(core_imagery,1) AS n_img
FROM style_preset WHERE NOT is_deleted;

SELECT knowledge_type, applicable_domain, count(*)
FROM plot_domain_knowledge WHERE NOT is_deleted GROUP BY 1,2 ORDER BY 3 DESC;
```

## 六、成本与已知限制

- **运行成本(单本 30 万字 ≈ 150 块)**：领域知识 ~0.5–1 元/本;文风蒸馏 ~1–3 元/本(map 150 块 + reduce 1 次),均以关思考模式计。
- **已知限制 / 后续优化**：
  1. 一期仅 TXT;PDF(文本层,`pypdf`)已在方案中预留,二期加开关即可。
  2. 文风蒸馏须"单作者/单风格一次";多风格混跑会污染聚合(CLI 未强制,靠使用规范)。
  3. 样本 < `STYLE_MIN_SAMPLE_WORDS` 时置信度打折并告警,结果仅供参考。
  4. `style_preset` 六维中"高频词/修辞明细"暂存 `ext`/`local_stats`;`style_scene_mapping` 场景级映射为二期。
  5. 领域术语近义去重靠 `DOMAIN_DEDUP_THRESHOLD`(默认 0.90)平衡,可按语料调。
  6. Novel Studio 侧读取 `style_preset` / RAG 召回 `plot_domain_knowledge` 的对接代码属 Node 侧改造,不在本工具范围。
