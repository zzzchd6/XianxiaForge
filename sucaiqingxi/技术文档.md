## 1. 设计定位（全局铁律）

- 原生 Python + 轻量库，**不引入重型框架**，**不耦合 Node 服务**（独立进程运行）。
- 向量强制 **512 维 bge**（`BAAI/bge-small-zh-v1.5`），与既有「诛仙库」同源同空间，**维度不可改**。
- `source_snippet`（原文片段）**仅供后台/溯源，禁止注入写作上下文**（防抄袭/串味）；文风表不落原文片段。
- `core_plot` / `content` 必须**抽象化/独立化**（禁原文人名地名功法宗门等专名），保证跨世界观复用。
- 全流程容错：失败重试、格式校验、异常数据跳过不中断整批；幂等可重跑。
- **诛仙原著库只读**：本工具全程不连、不写诛仙库，仅对齐其 bge 模型/维度与文风表字段。

## 4. 环境与安装

**技术栈**：Python 3.9+、PostgreSQL + pgvector（≥0.5，支持 HNSW）、sentence-transformers(bge)、
Flask（Web 控制台 + 向量服务）、numpy、psycopg2、requests、python-dotenv。

```bash
# 1) 虚拟环境（强烈建议；系统 python 可能缺 pgvector/依赖）
python -m venv .venv
.venv\Scripts\Activate.ps1            # Windows PowerShell

# 2) 依赖
pip install -r requirements.txt

# 3) 配置
copy .env.example .env                # 然后填入真实 DB / LLM 密钥

# 4) 建表（幂等，可重复执行；三个 DDL 都建在 novel_studio）
psql -h localhost -p 5432 -U noveluser -d novel_studio -f ddl-plot-material.sql
psql -h localhost -p 5432 -U noveluser -d novel_studio -f ddl-style-preset.sql
psql -h localhost -p 5432 -U noveluser -d novel_studio -f ddl-domain-knowledge.sql

# 5) 首次会下载 bge 模型（~100MB）。国内用镜像 HF_ENDPOINT=https://hf-mirror.com；
#    已缓存后设 HF_HUB_OFFLINE=1 跳过联网校验，避免超时。
```

> **无 psql 时的替代**：若机器未装 psql 客户端，可用项目自带 psycopg2 执行 DDL 文件
> （读取 .sql 文本后 `cur.execute`），效果等价 `psql -f`。
>
> 模型本地缓存路径：`C:\Users\<user>\.cache\huggingface\hub\`。
> **所有脚本请用 `.venv\Scripts\python.exe` 运行**，系统全局 python 可能缺 pgvector 等依赖。

## 6. 能力① 剧情素材 ETL（`extract_materials.py`）

抽取 4 类剧情素材：

| 类别 key | 中文 | 定义 |
|----------|------|------|
| `encounter` | 奇遇 | 主角因偶然/被迫/意外触发的非常规事件 → 重大收益或转折 |
| `foreshadow` | 伏笔手法 | 如何埋线→呼应→回收的可复用手法 |
| `highlight` | 人物高光 | 角色魅力集中爆发的名场面（逆袭/救场/立威/牺牲） |
| `task` | 剧情任务链 | 多阶段推进的目标驱动型结构（发布→阻碍→推进→完成/反转） |

### 6.1 全流程（`process_file` 编排）

源码按编号分段（`# 1) 清洗` … `# 9) 主流程`）。一次 `process_file` 顺序执行：

```
TXT → 1.读取 → 2.清洗 → 3.切块 → 4.章节预筛 → (验证时按 max_chunks 截断)
    → 5.并发 LLM 抽取(每块内含解析+校验) → 6.向量化 → 7.批内去重
    → 8.[dump 导出] → 9.dry-run 打样 或 入库(含库内去重)
```

- **6.1 读取 `read_txt`**：多编码回退 `utf-8 → gb18030 → gbk`，全失败则 `utf-8 errors=ignore`。
- **6.2 清洗 `clean_text`（逐行）**：删作者 PS/求票/本章说/网址/站点广告/分隔线/单独成行章节标题；
  乱码行（长度>10 且中文占比<20%）；相邻重复段落（最近 5 行去重）。
- **6.3 切块 `chunk_text`**：字符滑窗 `size=CHUNK_SIZE(2000)`，`step=size-overlap(200)`，丢弃 `<size/4` 尾碎块。
- **6.4 章节预筛 `should_skip_chunk`**（开关 `ENABLE_CHUNK_PREFILTER`）：本地零成本跳过明显无料块，不发 LLM。
  **极保守：两条件同时成立才跳**——事件词命中 `≤ PREFILTER_MIN_EVENTS(3)` **且** 对话占比 `≥ PREFILTER_MAX_DIALOGUE(0.5)`；`<150` 字残块直接跳。
- **6.5 并发抽取 `extract_from_chunk`**（线程池 `max_workers=LLM_CONCURRENCY`）：每块 `build_messages`→`call_llm`→`parse_json`→
  遍历 4 类各取前 `MAX_MATERIALS_PER_CHUNK(3)` 条 `validate_material`。**单块异常/解析失败只记日志、返回空，不中断**。
- **6.6 向量化 `vectorize`**：对所有 `core_plot` 批量 `bge_embedder.embed_texts`（512 维、归一化）。**维度自检**：≠512 直接报错。
- **6.7 批内去重 `dedup_in_batch`**：**同类内**归一化向量点积=余弦，`> DEDUP_THRESHOLD(0.86)` 视为重复簇，按质量分降序**簇内只留最高分**。
- **6.8 导出（`--dump FILE`）**：survivors 导出 JSON（不含 embedding），供人工核对。
- **6.9 入库 `persist`→`upsert_material`**（`--dry-run` 跳过）：逐条**库内去重**（同表同 project_id 作用域 pgvector 最近邻）：
  相似度 `>阈值` 且库内质量 `≥` 新 → **skip**；超阈但新的更高 → **update**（保留 id）；否则 → **insert**。**逐条提交**，单条失败 rollback 跳过。

### 6.2 关键校验 `validate_material`（不合格丢弃）

- 缺 `title`/`core_plot`、或 `core_plot <20` 字 → 丢；
- `_strip_leaked_fields` 剥离 core_plot 尾部混入的其它字段；
- `quality_score` 夹到 0-10，`< MIN_QUALITY_TO_STORE(6)` → 丢；
- `applicable_scene_type` 不在 `{key,transition,foreshadow}` → 置 None；
- 长度裁剪：title 200 / core_plot 4000 / trigger·reward·cost 2000 / emotional_beat 1000 / source_work 100 / **source_snippet 80** / tags ≤8 个各 ≤50。

### 6.3 CLI

```bash
python extract_materials.py <TXT文件或目录> [--source-work 作品名] [--dry-run] [--max-chunks N] [--dump FILE]
```

| 参数 | 作用 |
|------|------|
| `path` | TXT 文件或目录（目录递归收集所有 .txt 并排序） |
| `--source-work` | 指定作品名；默认取文件名 |

## 7. 能力② 作者文风蒸馏（`distill_style.py`）

把**同一作者的多本 TXT** 蒸馏成**一套结构化文风配置**（6 大维度），写入 `style_preset`（幂等 upsert）。
复用 ① 的读取/清洗/切块/LLM/连接底座（`import extract_materials as em`），额外实现 **map-reduce**。

### 7.1 6 大文风维度

| 维度 | 落库字段 | 内容 |
|------|----------|------|
| ① 创作心智 | `mental_models` / `decision_heuristics` | 作者潜在世界观、剧情推进的决策习惯 |
| ② 描写比例 | `description_ratio`(JSONB) | 场景/动作/对话/心理占比 + `rhythm_notes` 节奏 |
| ③ 句式段落 | `sentence_rules`(JSONB) | 平均句长/长短句偏好/转场手法/段落长度 |
| ④ 意象与禁忌 | `core_imagery` / `forbidden_words` | 专属意象库 / 禁用表达 |
| ⑤ 视角叙事 | `perspective_rules` | 人称、视角切换、叙事距离规则 |
| ⑥ 反模式 | `anti_patterns` | 作者刻意规避的套路/避坑 |

### 7.2 map-reduce 流程

```
多本 TXT → 合并清洗 → 切块 → [本地零成本量化 local_stats]
  → map：逐块用 6 维 Prompt 抽取局部风格特征（并发）
  → reduce：高频 TopK 聚合（数组维度取 Top-STYLE_TOPK=12）+ 数值维度加权平均
            → 再送 1 次 LLM 归纳为整体文风
  → compute_confidence → persist_style_preset（幂等 upsert）
```

- **本地量化 `local_stats`**：零 LLM 成本统计平均句长、对话占比、四字格密度等，落 `local_stats`(JSONB)。
- **compute_confidence**（0-100）：
  `sample_ratio = min(1, 样本字数 / 50000)`；`coverage = 已覆盖维度数 / 6`；`block_factor = min(1, 块数 / 20)`；
  `confidence = round(100 * (0.5*sample_ratio + 0.3*coverage + 0.2*block_factor), 2)`；
  `quality_score = max(1, min(10, round(confidence/10)))`。
  > ⚠️ 小样本 `--dry-run` 时 sample_ratio 仍按全文字数计，置信度可能偏高，正式蒸馏需 ≥ `STYLE_MIN_SAMPLE_WORDS(50000)` 字。
- **持久化 `persist_style_preset`**（幂等键 = `style_name` + project 作用域）：
  已存在 → `UPDATE ..., update_time=NOW(), "version"="version"+1`；否则 `INSERT`。风格表**不落 `source_snippet`**（防串味）。

### 7.3 CLI

```bash
python distill_style.py <TXT文件或目录> --style-name "忘语·凡人流" [--author 忘语] [--dry-run] [--max-chunks N]
```

| 参数 | 作用 |
|------|------|
| `path` | 单本 TXT 或目录（目录=同作者多本合并蒸馏） |
| `--style-name` | **必填**，预设名（幂等键；重复蒸馏即更新版本） |
| `--author` | 作者名（可选） |
| `--dry-run` | 只蒸馏打印结果，不入库 |
| `--max-chunks N` | 只处理前 N 块（验证用） |

## 8. 能力③ 专业领域知识蒸馏（`extract_domain_knowledge.py`）

把**专业书籍 TXT**（中医/刑侦/军事…）蒸馏成 **5 类领域知识条目**，写入 `plot_domain_knowledge`（两级去重）。
同样复用 ① 底座，管线与 ① 高度同构（清洗→切块→并发抽取→向量化→批内去重→库内去重入库）。

### 8.1 5 类知识（`knowledge_type` 枚举）

| type | 含义 |
|------|------|
| `term` | 术语/概念定义 |
| `rule` | 规则/原理/机理 |
| `pitfall` | 常见误区/易错点 |
| `expression` | 专业表达/行话 |
| `case` | 典型案例/示例 |

### 8.2 关键参数与校验

- `content` 是**唯一向量化字段**，要求 ≥30 字（正文建议 100-300 字，超 `DOMAIN_CONTENT_MAXLEN(300)` 裁剪）。

- `source_snippet` 入库裁剪 ≤120 字，**仅后台可见，禁止进写作上下文**。
- **两级去重**：同 `knowledge_type` 内，批内 + 库内向量近邻，`> DOMAIN_DEDUP_THRESHOLD(0.90)` 视为重复。

## 11. 成本与性能

- **省钱三招**：章节预筛本地跳无料块（不发 LLM）；文风本地量化 `local_stats` 零成本；两级去重减少无效入库。
- **并发**：LLM 抽取线程池 `LLM_CONCURRENCY`（默认 4），受 LLM 限流与本机核数约束。
- **向量化**：CPU 上 bge batch=32 较稳；大批量建议 `EMBEDDING_DEVICE=cuda`。
- 经验：单本长篇（数百万字）dry-run 打样分钟级；全量入库主要耗时在 LLM 抽取与逐条库内去重。

## 12. 运维与排障

| 现象 | 原因 | 处理 |
|------|------|------|
| 控制台中文乱码 | PowerShell 用 GBK 渲染 UTF-8 输出 | 非 bug；GUI 子进程已强制 `PYTHONIOENCODING=utf-8` 捕获无乱码 |
| `维度 X ≠ 512` 报错 | EMBEDDING_MODEL 非 512 维 | 换回 `bge-small-zh-v1.5`，铁律不可改 |
| 首次运行卡在下载模型 | 拉 HuggingFace 权重 | 设 `HF_ENDPOINT=https://hf-mirror.com`；已缓存后 `HF_HUB_OFFLINE=1` |
| `psql` 命令不存在 | 未装 psql 客户端 | 用 psycopg2 读 `.sql` 文本后 `cur.execute` 等价执行 |
| 端口 8610 占用 | 旧 GUI 进程未退 | `Get-NetTCPConnection -LocalPort 8610` 查 PID 后 `Stop-Process`（需权限） |
| 大量块被跳过 | 预筛过激 | 关 `ENABLE_CHUNK_PREFILTER` 或调低 `PREFILTER_MAX_DIALOGUE` |
| 解析失败块 | LLM 返回非法 JSON | 记 `etl_failures.log`，自动跳过不中断 |

## 13. 结果查询 SQL（速查）

```sql
-- 某类素材按质量排序
SELECT id,title,quality_score,applicable_scene_type,source_work
FROM plot_material_encounter WHERE NOT is_deleted ORDER BY quality_score DESC LIMIT 50;

-- 文风预设总览
SELECT id,style_name,author,confidence,quality_score,sample_word_count,"version",update_time
FROM style_preset WHERE NOT is_deleted;

-- 领域知识按类型统计
SELECT knowledge_type,applicable_domain,count(*)
FROM plot_domain_knowledge WHERE NOT is_deleted GROUP BY 1,2 ORDER BY 3 DESC;

-- 向量语义召回示例（top-2，:qvec 为 512 维 bge 查询向量）
SELECT id,title,1-(embedding <=> :qvec) AS score
FROM plot_material_encounter
WHERE NOT is_deleted AND embedding IS NOT NULL
ORDER BY embedding <=> :qvec LIMIT 2;
```

## 15. 已知限制

- LLM 抽取质量依赖模型能力与 Prompt，`core_plot`/`content` 抽象化非 100% 可靠，需人工抽检。
- 文风小样本置信度可能虚高（见 §7.2）；正式蒸馏需足量样本。
- 库内去重是「同表/同类 + project 作用域」近邻，跨类语义重复不去。
- GUI 为单机本地工具，无鉴权，**不要暴露公网**。
- `source_snippet` 已在多处强约束禁入写作上下文，接入方仍须在召回层再次确认不返回该字段。
