## 一、需求背景与问题定义

### 1.1 现状描述

当前系统的大纲与场景脚本是**线性结构**：
- 场景节点按 `sortOrder` 顺序排列，1 对 1 关系
- 章节计划按顺序生成，对应线性的场景节点
- 剧情分支功能在**章节阅读层**实现（选分支 → 影响台账 → 状态变化）
- 分支选择后，**大纲/场景脚本不感知**，仍然是原来的线性结构

### 1.2 核心问题

用户的创作流程出现了**三层脱钩**：

| 层面 | 脱钩表现 | 影响 |
|------|---------|------|
| **数据层** | 场景节点是线性的，分支选择在章节层，两层数据无关联 | 无法追溯"这个分支对应哪段大纲" |
| **逻辑层** | 分支后人物状态/伏笔/方向都变了，但后续大纲还是原设定 | 生成后续章节时上下文不一致 |
| **体验层** | 用户知道"大纲已经不对了"，但不知道怎么改，也懒得手动改 | 大纲逐渐失去参考价值，变成"摆设" |

### 1.3 问题本质

**大纲是"线性规划"的，但实际创作是"分支演进"的。**

当前架构把"规划"和"创作"分成了两个独立的层，规划层（大纲）不感知创作层（分支选择）的变化，导致两层逐渐脱节。

### 1.4 目标愿景

把大纲从**"线性写作计划"**升级为**"剧情地图"**——不是一条路走到黑，而是一张有分叉、有汇合、有探索空间的地图。作者在地图上规划，AI 沿着选定的路径生成，走岔了也不怕，因为地图还在，随时可以换条路走。

## 二、JTBD 分析（Jobs-to-be-Done）

### 2.1 目标用户

**核心用户画像**：使用 AI 辅助创作长篇仙侠/玄幻小说的独立作者，具备一定技术能力，追求对创作过程的深度掌控。

### 2.2 功能任务（Functional Jobs）

| 编号 | 功能任务 | 重要性 |
|------|---------|--------|
| FJ-01 | 规划多条剧情分支路径，探索不同的故事走向 | ★★★★★ |
| FJ-02 | 在分支点对比不同选择的后续影响，做出决策 | ★★★★☆ |
| FJ-03 | 确保分支后的剧情与世界观设定保持一致 | ★★★★★ |
| FJ-04 | 管理多条分支线，知道哪条是主线、哪条是废案 | ★★★★☆ |
| FJ-05 | 从分支点重新生成后续内容，尝试不同可能性 | ★★★★☆ |
| FJ-06 | 追踪伏笔在不同分支中的状态（哪条线埋了、哪条线收了） | ★★★☆☆ |

### 2.3 情感任务（Emotional Jobs）

| 编号 | 情感任务 | 重要性 |
|------|---------|--------|
| EJ-01 | 对剧情走向有掌控感，而不是被 AI 牵着走 | ★★★★★ |
| EJ-02 | 探索"如果当时选了另一条路会怎样"的好奇心 | ★★★★☆ |
| EJ-03 | 避免"写崩了"的焦虑，有安全感（随时可以回退） | ★★★★★ |
| EJ-04 | 感觉自己是"导演"，在指挥剧情走向 | ★★★☆☆ |

### 2.4 痛点（Pains）

| 编号 | 痛点 | 强度 | 当前 workaround |
|------|------|------|-----------------|
| P-01 | 选了分支之后，原来的大纲就废了，前后不一致 | 🔴 高 | 手动改大纲，或者干脆不看大纲了 |
| P-02 | 想试试不同的分支走向，但怕改不回来 | 🔴 高 | 复制整个项目，在副本里试 |
| P-03 | 不知道分支后伏笔的状态对不对 | 🟡 中 | 靠脑子记，或者翻聊天记录 |
| P-04 | 分支多了之后，搞不清哪条是哪条 | 🟡 中 | 用笔记下来 |
| P-05 | 想对比两条分支的优劣，但没法并排看 | 🟡 中 | 手动翻来翻去对比 |
| P-06 | 分支汇合点写不好，容易出戏 | 🟡 中 | 反复改好几遍 |

### 2.5 收益（Gains）

| 编号 | 收益 | 类型 |
|------|------|------|
| G-01 | 大纲始终跟实际剧情同步，有参考价值 | 期望型 |
| G-02 | 可以放心大胆地探索分支，不怕写崩 | 兴奋型 |
| G-03 | 一眼看到全局剧情结构，像看地图一样 | 期望型 |
| G-04 | 伏笔/状态自动感知分支，不用手动管 | 期望型 |
| G-05 | 可以保存多条分支线，作为素材库 | 兴奋型 |
| G-06 | 生成质量更高，因为上下文更准确 | 基础型 |

## 三、产品目标与成功指标

### 3.1 产品目标

**核心目标**：解决"分支后大纲脱钩"问题，让大纲从线性计划升级为分支感知的剧情地图。

**战略价值**：
- 强化"叙事工程"差异化定位（竞品没有的能力）
- 提升用户对创作过程的掌控感（高互动创作模式）
- 为未来的"多结局互动小说"模式打基础

### 3.2 成功指标

| 指标 | 定义 | 目标值 | 衡量方式 |
|------|------|--------|---------|
| **分支使用率** | 使用分支功能的章节占比 | ≥ 30% | 后台统计 |
| **大纲参考率** | 生成章节前查看大纲的用户比例 | ≥ 60% | 行为埋点 |
| **分支回退率** | 选了分支又回退的比例 | ≤ 15% | 后台统计 |
| **用户满意度** | 对分支功能的满意度评分 | ≥ 4.2/5 | 用户调研 |

## 四、用户故事与验收标准

### Epic：场景脚本分支感知

> **作为**使用 AI 辅助创作长篇小说的作者
> **我想要**大纲和场景脚本能够感知剧情分支
> **这样**分支后的剧情就能和大纲保持一致，我也能在地图上规划多条故事线

### User Story 1：场景节点分支化

**Summary**：支持在场景脚本中创建分支点，每个分支有独立的后续场景链

**Use Case**：
- **As a** 作者
- **I want to** 在场景节点上创建分支，每个分支有自己的后续场景
- **so that** 我可以在规划阶段就设计好多条剧情路径

**Acceptance Criteria**：

```gherkin
Scenario: 创建分支点
  Given 我在场景脚本的列表视图
  When 我在某个场景节点上点击"添加分支"
  Then 该节点变为分支点类型
  And 自动创建两个子分支节点
  And 每个子节点有默认名称"分支A""分支B"
  And 分支节点用不同颜色区分

Scenario: 编辑分支选项
  Given 我有一个分支点节点
  When 我点击分支点的"编辑选项"
  Then 弹出选项编辑面板
  And 我可以添加/删除/排序分支选项
  And 每个选项可以设置：选项文本、标签、描述
  And 保存后分支点显示更新后的选项

Scenario: 删除分支
  Given 我有一个分支点，下面有3条分支
  When 我删除其中一条分支
  Then 该分支及其所有后续节点被标记为已删除
  And 分支点还在，剩下的分支正常显示
  And 有撤销删除的选项（30秒内）
```

```gherkin
Scenario: 汇合点信息

  And 可以编辑汇合点的"汇合说明"（用于AI生成时的上下文）
```

## 五、功能需求详细设计

### 5.1 数据模型设计

#### 5.1.1 场景节点表改造（scene_node）

新增字段：

| 字段 | 类型 | 说明 | 默认值 |
|------|------|------|--------|
| `node_type` | enum | `linear`（普通节点）/ `branch_point`（分支点）/ `merge_point`（汇合点） | `linear` |
| `branch_group_id` | int | 同一组分支的节点共享 ID，用于标识"这几个节点是同一个分支点的不同路径" | NULL |
| `path_label` | varchar(100) | 路径标签（如"正道线""魔道路线"） | NULL |
| `is_canon` | boolean | 是否主线 | true |
| `branch_options` | jsonb | 分支选项列表（仅 branch_point 类型有） | NULL |

**branch_options 结构**：
```json
[
  {
    "id": "opt_1",
    "text": "接受掌门的考验",
    "label": "正道",
    "description": "走正道，获得掌门赏识",
    "sort_order": 1
  },
  {
    "id": "opt_2",
    "text": "偷偷溜走",
    "label": "隐忍",
    "description": "低调行事，避免引人注目",
    "sort_order": 2
  }
]
```

#### 5.1.2 新增场景边表（scene_edge）

**为什么不用 parent_id 自关联？**
- 自关联只能表示 1 对多，不能表示多对 1（汇合）
- 未来扩展条件分支、概率分支不方便
- 边表是图结构的标准做法，更灵活

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int | 主键 |
| `outline_id` | int | 所属大纲（卷） |
| `from_node_id` | int | 起始节点 |
| `to_node_id` | int | 目标节点 |
| `edge_type` | enum | `sequence`（顺序）/ `choice`（选择分支）/ `conditional`（条件分支） |
| `condition` | jsonb | 分支条件（选项描述、前置条件等） |
| `sort_order` | int | 同一 from_node 的边的排序 |
| `created_at` | timestamp | 创建时间 |
| `updated_at` | timestamp | 更新时间 |

**索引**：
- `outline_id` + `from_node_id`（查询某节点的后续边）
- `outline_id` + `to_node_id`（查询某节点的前置边）

#### 5.1.3 章节计划表改造（chapter_plan）

新增字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `branch_path` | jsonb | 本章走的分支路径（节点 ID 数组），如 `[1, 2, 3, 5, 8]` |
| `branch_path_hash` | varchar(64) | 路径哈希，用于快速判断两个章节是不是同一条分支 |

**为什么存路径数组而不是只存当前节点？**
- 生成时需要完整路径的上下文（"前面选了哪些分支"）
- 方便做分支对比
- 虽然冗余，但查询方便，空间换时间

#### 5.1.4 伏笔表改造（foreshadow_thread）

新增字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `branch_path_hash` | varchar(64) | 所属分支路径哈希，NULL 表示全局/主线 |
| `is_branch_derived` | boolean | 是否分支衍生伏笔 | false |

### 5.2 UI 交互设计

#### 5.2.1 三种视图

| 视图 | 适用场景 | 布局 |
|------|---------|------|
| **列表视图** | 日常编辑、线性剧情 | 垂直列表，分支节点左侧有颜色条标识 |
| **流程图视图** | 看全局结构、分支规划 | 横向流程图，节点+连线，分支点分叉 |
| **树状视图** | 多分支复杂剧情 | 纵向树状，折叠展开 |

**默认视图**：列表视图（日常编辑效率最高）
**视图记忆**：上次使用的视图存在 localStorage

#### 5.2.2 列表视图的分支表现

- 普通节点：白色/默认背景
- 分支点节点：左侧有分叉图标 + 分支选项预览
- 分支节点：左侧有颜色条（不同分支不同颜色）
- 汇合点节点：左侧有汇合图标
- 废案分支：灰色背景，文字淡化

#### 5.2.3 分支点交互

**创建分支**：
- 节点右键菜单 → "添加分支"
- 或者节点底部的 "+ 分支" 按钮
- 创建后自动生成两个子节点

**编辑分支选项**：
- 点击分支点节点上的"选项"按钮
- 弹出侧边面板，编辑选项列表
- 支持添加/删除/排序
- 每个选项可以设置：文本、标签、描述、颜色

**删除分支**：
- 右键分支节点 → "删除此分支"
- 弹出确认："将删除此分支及其后续 X 个节点，确定吗？"
- 30 秒内可撤销

#### 5.2.4 汇合点交互

**创建汇合**：
- 拖拽两条分支的末端到一起
- 或者右键 → "设为汇合点"
- 汇合点自动连接所有汇入的分支

**汇合点信息**：
- 显示哪些分支汇入
- 显示"汇合说明"（用于 AI 生成的上下文）
- 可以编辑汇合说明

#### 5.2.5 路径管理

**顶部路径面包屑**：
```
主线 → 青云山篇 → 比武分支 → 胜出线
```

- 点击面包屑可以切换路径
- 下拉显示所有可用路径
- 主路径有星标标记

**路径操作**：
- 重命名路径
- 设为主线
- 标记为废案
- 复制路径（基于某条分支新建一条）
- 路径对比

### 5.3 生成逻辑改造

#### 5.3.1 分支上下文注入

ContextComposer 新增分支历史注入逻辑：

```
【分支历史】
- 第3章选择了"接受掌门考验"（正道线）
  → 影响：与掌门关系+20，获得"青云剑诀"
  → 状态：境界提升至炼气七层
- 第5章选择了"隐瞒真相"（隐忍线）
  → 影响：心理压力+30，与师姐关系-10
  → 伏笔：新增"师姐的怀疑"伏笔
```

**注入时机**：
- 在构建章节生成上下文时
- 读取当前章节的 `branch_path`
- 沿着路径回溯，收集所有分支点的选择和影响
- 格式化后注入 prompt

#### 5.3.2 分支点章节自动生成选项

生成到分支点章节时，自动执行：
1. 正常生成章节正文
2. 分析章节结尾的剧情张力
3. 生成 2-3 个合理的分支选项
4. 每个选项包含：选项文本、简短描述、影响预览
5. 展示给用户选择

**影响预览的生成**：
- 不是精确数值，是方向性描述
- 例如："可能获得掌门赏识"、"可能引起师姐怀疑"
- 避免剧透太多，保持探索感

### 5.4 联动模块改造

#### 5.4.1 伏笔台账

- 新增"按分支筛选"功能
- 伏笔详情显示"所属分支"
- 分支衍生伏笔有特殊标记
- 超期检测按分支路径计算

#### 5.4.2 时间线

- 已经有分支感知了，保持即可
- 新增"分支时间线对比"视图
- 不同分支的时间线并排展示

#### 5.4.3 人物状态快照

- 已经有分支感知了，保持即可
- 新增"分支状态对比"功能
- 同一人物在不同分支的状态对比

#### 5.4.4 叙事体检

新增 2 个维度：

| 维度 | 说明 | 计算方式 |
|------|------|---------|
| **分支健康度** | 分支分布是否均衡 | 分支数量、长度差异、汇合点比例 |
| **分支一致性** | 不同分支设定是否矛盾 | 跨分支的人物/设定冲突检测 |

## 六、非功能需求

### 6.1 性能要求

| 指标 | 要求 |
|------|------|
| 场景列表加载 | ≤ 1s（100 个节点以内） |
| 流程图渲染 | ≤ 2s（100 个节点以内） |
| 分支切换 | ≤ 500ms |
| 路径对比 | ≤ 1s（两条路径各 50 节点以内） |

### 6.2 兼容性要求

- 向后兼容：现有线性场景数据自动迁移为 `linear` 类型
- 数据迁移：一次性迁移脚本，不影响现有数据
- 降级方案：流程图视图性能差时，自动降级为列表视图

### 6.3 可扩展性要求

- 边表设计支持未来扩展：条件分支、概率分支、并行分支
- 节点类型可扩展：不只是 linear/branch_point/merge_point
- 视图可扩展：未来可以加时间线视图、节奏曲线视图等

## 八、风险与依赖

### 8.1 技术风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|---------|
| 流程图视图性能问题 | 高 | 中 | 限制渲染节点数，大数据时降级为列表 |
| 数据迁移出错 | 高 | 低 | 先备份，写测试用例，灰度迁移 |
| 分支上下文注入效果不好 | 中 | 中 | 多迭代 prompt，加人工审核环节 |

### 8.2 依赖项

| 依赖 | 说明 |
|------|------|
| 现有场景脚本模块 | 在现有基础上改造，不是重做 |
| 章节生成管线 | ContextComposer 需要改造 |
| 伏笔台账 | 需要加分支筛选 |
| 叙事体检 | 需要加新维度 |

### 8.3 范围风险

**风险**：越做越大，从"分支感知"变成"完整的互动小说引擎"

**应对**：
- 明确 MVP 范围：阶段一+阶段三是核心，必须做完
- 阶段二和阶段四是增强，可以往后放
- 不做：条件分支、概率分支、并行分支（太复杂，当前用不上）

## 十、附录

### 10.1 术语表

| 术语 | 说明 |
|------|------|
| **分支点（Branch Point）** | 剧情分叉的节点，有多个后续路径 |
| **汇合点（Merge Point）** | 多条分支线汇合的节点 |
| **分支路径（Branch Path）** | 从起点到当前节点经过的所有节点序列 |
| **主线（Canon）** | 默认的、主要的剧情线 |
| **废案（Scrap）** | 被放弃的分支线，保留但不显示在主视图 |
| **节点类型（Node Type）** | linear / branch_point / merge_point |
| **边类型（Edge Type）** | sequence / choice / conditional |
