## 十、竞品对标与差异化定位建议（按模块逐个对标）

> **说明**：本章按 14 个核心模块分别与竞品对标，每个模块分析：竞品有哪些、竞品优点是什么、我们现状如何、我们的差异化优势在哪、可以借鉴什么。
>
> **竞品分类**：
> - **AI 写作类**：NovelAI、Claude、ChatGPT、秘塔写作猫、彩云小梦
> - **小说创作工具类**：橙瓜、小黑屋、墨者写作、壹写作
> - **世界观设定类**：World Anvil、黑曜石（Obsidian）、Notion
> - **编剧/叙事工具类**：Final Draft、Plottr、Scrivener
> - **游戏/其他类**：各类修仙游戏、卡牌游戏、数据看板产品

---

### 10.1 侧边栏 / 信息架构

#### 竞品一览

| 竞品类型 | 代表产品 | 信息架构特点 |
|----------|----------|-------------|
| 知识管理 | Notion、Obsidian | 左侧分组+折叠，支持自定义排序 |
| 设计工具 | Figma、Sketch | 左侧图层+右侧属性，中间画布 |
| 写作工具 | Scrivener、壹写作 | 按文档类型分组，支持自定义 |
| 游戏 | 各类修仙手游 | 境界/功法/丹药/任务等分类清晰，有图标有颜色 |

#### 竞品优点

| 产品 | 优点 |
|------|------|
| **Notion** | 左侧导航分组+折叠，支持自定义排序和隐藏；页面可以嵌套，层级清晰 |
| **Obsidian** | 全局搜索（Cmd+K）快速跳转，支持命令面板；最近访问文件置顶 |
| **Figma** | 最近文件+常用文件置顶；左侧图层树支持折叠展开 |
| **墨刀** | 左侧按工作流分组，新手引导清晰 |
| **修仙游戏** | 菜单分类清晰（境界/功法/丹药/任务/背包），每个分类有独特图标和颜色，一眼就能区分 |

#### 我们的现状

- 16 个菜单项完全平铺，无分组、无折叠
- 命名风格不统一（文艺名+直白名混用）
- 顺序不符合创作工作流（三个自定义模块放在世界观前面）
- 无全局搜索、无最近访问、无快捷键
- 仙侠氛围不足，像普通后台管理系统

#### 我们的差异化优势

| 优势 | 说明 |
|------|------|
| **功能深度远超竞品** | 竞品一般只有 5-8 个核心功能，我们有 16 个模块，覆盖从世界观到质检的全流程 |
| **仙侠主题天然适合游戏化导航** | 竞品都是通用工具，导航设计偏中性；我们可以把导航做成"修仙界面"，每个菜单对应一个修仙概念 |
| **叙事工程概念独特** | "伏笔台账""叙事体检""方向统计"这些模块是竞品没有的，导航设计可以突出这个差异化 |

#### 可借鉴点

| 借鉴点 | 来源 | 具体做法 |
|--------|------|----------|
| 菜单分组+折叠 | Notion | 按创作工作流分为 5 组：创作主线 / 世界搭建 / 叙事工程 / 质量防线 / 素材与配置 |
| 全局快速跳转 | Obsidian | Cmd+K 全局搜索，支持搜菜单、人物、章节、伏笔等 |
| 最近访问 | Figma | 最近打开的页面/实体置顶，快速回到上次工作 |
| 仙侠风格菜单 | 修仙游戏 | 每个菜单项配仙侠风格图标和颜色，hover 有动效 |
| 按工作流排序 | 墨刀 | 从世界观→大纲→生成→编辑→质检，符合创作流程 |

### 10.2 仪表盘 / 首页

#### 竞品一览

| 竞品类型 | 代表产品 | 仪表盘特点 |
|----------|----------|-----------|
| 知识管理 | Notion 首页 | 最近访问+快速新建+工作概览 |
| 开发平台 | GitHub Dashboard | 待办+活动流+项目概览 |
| 数据看板 | Tableau、各种 BI 工具 | KPI 卡片+趋势图+待办 |
| 游戏 | 各类游戏主界面 | 角色状态+任务+活动入口 |

#### 竞品优点

| 产品 | 优点 |
|------|------|
| **Notion 首页** | 快速操作入口明显（新建页面、导入等）；最近访问文件列表，一键继续 |
| **GitHub Dashboard** | 待办聚合（issues、PR、通知）；活动流实时更新；项目概览卡片 |
| **数据看板产品** | KPI 卡片一目了然；趋势图展示变化；异常指标高亮提醒 |
| **游戏主界面** | 角色状态（血量/蓝量/等级）直观；任务引导清晰；活动入口醒目 |

#### 我们的现状

- 6 个卡片：双库状态 / 创作热力图 / 伏笔回收进度 / 方向均衡度 / 我的项目 / 最近生成任务
- 最大面积给了热力图，但价值最低
- 没有全书概览关键指标（总字数/总章节/出场人物/伏笔数/质量评分）
- 没有待办提醒聚合
- 没有快速操作入口
- 定位是"数据展示板"，不是"驾驶舱"

#### 我们的差异化优势

| 优势 | 说明 |
|------|------|
| **叙事健康度概念独特** | 竞品只有字数/进度统计，我们有"叙事体检""伏笔回收进度""方向均衡度"等叙事质量指标 |
| **创作热力图有特色** | 类似 GitHub 贡献图，但展示的是创作活跃度，有游戏化激励效果 |
| **多维度数据丰富** | 竞品一般只有 2-3 个维度，我们有 9 维叙事体检+方向均衡度+伏笔状态等多维度数据 |

#### 可借鉴点

| 借鉴点 | 来源 | 具体做法 |
|--------|------|----------|
| KPI 概览卡片 | 数据看板产品 | 顶部放全书关键指标：总字数/总章节/出场人物/伏笔数/质量评分 |
| 待办聚合 | GitHub | 左侧待办区：伏笔到期/生成失败/待审计 等聚合展示 |
| 快速操作 | Notion | 右侧快速操作区：新建章节/开始生成/跑体检 等一键操作 |
| 状态概览 | 游戏主界面 | 把仪表盘做成"修仙洞府"风格：修为进度/境界/丹药/任务 |
| 趋势分析 | 数据看板 | 增加趋势图：字数增长趋势、质量变化趋势、伏笔回收趋势 |

### 10.3 世界观百科

#### 竞品一览

| 竞品类型 | 代表产品 | 世界观特点 |
|----------|----------|-----------|
| 百科 | 维基百科 | 信息结构化+双向链接+分类索引 |
| 关系图谱 | Neo4j Browser | 可视化关系网络+探索式交互 |
| 世界观工具 | World Anvil | 世界设定结构化+时间线+地图 |
| 知识管理 | Obsidian | 双向链接+图谱视图+标签 |
| AI 写作 | NovelAI、Claude | 没有结构化世界观，纯文本生成 |

#### 竞品优点

| 产品 | 优点 |
|------|------|
| **维基百科** | 信息结构化程度高；双向链接丰富（任何名词都能点）；分类索引清晰 |
| **Neo4j Browser** | 力导向图可视化关系网络；支持探索式交互（点击节点展开）；搜索定位准确 |
| **World Anvil** | 世界设定管理最专业；支持时间线、地图、家族树等；社区模板丰富 |
| **Obsidian** | 双向链接体验极佳；图谱视图美观；标签系统灵活 |

#### 我们的现状

- 8 类实体：人物/门派/地点/功法/法宝/妖兽/丹药灵材/日常信物
- 人物详情三 Tab：设定/关系/深度蒸馏（写作画像）
- 功法详情两 Tab：设定/蒸馏
- 人物关系只有列表，无关系图谱
- 写作画像直接 JSON.stringify，无可视化
- 搜索有 bug（不能用）
- 诛仙库和自定义实体分开（4 个模块分散）
- 缺少出场章节列表、人物状态时间线
- 缺少实体双向链接

#### 我们的差异化优势

| 优势 | 说明 |
|------|------|
| **结构化数据库 + 向量检索** | 竞品要么纯结构化（World Anvil）要么纯文本（Obsidian），我们是结构化+向量检索结合 |
| **写作画像（深度蒸馏）** | 竞品没有这个功能——我们能从人物设定中蒸馏出"写作画像"，生成时自动注入，保证人物一致性 |
| **与生成管线深度联动** | 竞品的世界观是"静态资料库"，我们的世界观是"生成的燃料"——世界观数据直接驱动 AI 生成 |
| **功法招式结构化** | 竞品的功法/技能一般只有描述，我们的招式是结构化的（名字/效果/消耗/冷却等） |
| **诛仙级别的数据量** | 竞品需要用户从零开始建，我们自带一整本小说的结构化数据（18 张表、数百个实体） |

#### 可借鉴点

| 借鉴点 | 来源 | 具体做法 |
|--------|------|----------|
| 关系图谱视图 | Neo4j、Obsidian | 人物关系用力导向图可视化，点击节点展开详情 |
| 双向链接 | 维基百科、Obsidian | 任何地方提到实体名都可点击跳转；实体详情页显示"被引用"列表 |
| 出场章节列表 | World Anvil | 人物详情加"出场章节"Tab，点击跳转对应章节 |
| 世界观统一展示 | — | 统一展示诛仙库+自定义实体，用标签区分来源，不要分散在 4 个模块 |
| 全局世界观图谱 | — | 所有实体和关系都在一张图上，像 Google Maps 一样探索（大杀器功能） |

### 10.4 自定义功法坊

#### 竞品一览

| 竞品类型 | 代表产品 | 功法/技能特点 |
|----------|----------|---------------|
| ARPG | 暗黑破坏神、Path of Exile | 可视化技能树+节点选择+预览 |
| 卡牌游戏 | 炉石传说、影之诗 | 卡牌设计+稀有度+卡组构建 |
| 角色创建 | 黑魂、艾尔登法环 | 职业选择+属性分配+实时预览 |
| 修仙游戏 | 各类修仙手游 | 功法升级+突破+境界系统 |

#### 竞品优点

| 产品 | 优点 |
|------|------|
| **暗黑/POE 技能树** | 可视化技能树，节点清晰；路径选择有策略深度；hover 预览效果 |
| **炉石/影之诗** | 卡牌设计精美（插画+数值+效果）；稀有度系统（普通/稀有/史诗/传说）；卡组构建有策略性 |
| **黑魂/艾尔登法环** | 角色创建时实时预览外观变化；属性分配有取舍；职业选择有明确风格定位 |
| **修仙手游** | 功法升级有成就感（进度条+突破动画）；境界系统清晰；功法搭配有策略性 |

#### 我们的现状

- 功法卡片：名字 + 道则标签 + 深度徽标 + 攻击方向 chips
- 详情 Dialog：道则构型/本源运用方向/适配门槛/分道境神通/典型运用技巧/反噬代价/演化方向/身体印记/功法详解
- 千人千面变种：基于四因子（主道则×种族×性格×出身）确定性推导
- 创建向导三步：道则构型/行功根骨/衍化配置
- 左侧预览栏显示当前配置汇总（非实时 AI 详解）
- 有"一键全随机"按钮
- 道则选择有对冲警告
- 列表无筛选排序，无搜索框，无批量操作

#### 我们的差异化优势

| 优势 | 说明 |
|------|------|
| **千人千面变种系统** | 竞品的功法/技能是固定的，我们的功法基于四因子确定性推导变种——同一功法不同人练效果不同，这是小说创作的独特需求 |
| **九大本源道则体系** | 竞品的技能树一般是"职业→技能"的树状结构，我们是"道则→方向→功法"的组合式体系，更灵活、更有深度 |
| **功法详解 AI 生成** | 竞品的技能描述是固定的，我们可以根据参数动态生成功法详解，每个功法都有独特的描述 |
| **变种差异存储（offsets）** | 设计非常聪明——只存相对偏移量，不存完整副本，原功法改了变种自动更新 |

#### 可借鉴点

| 借鉴点 | 来源 | 具体做法 |
|--------|------|----------|
| 功法树可视化 | 暗黑/POE | 把道则→方向→功法做成可视化树状图，点击节点查看详情 |
| 稀有度系统 | 卡牌游戏 | 功法/变种分稀有度（普通/显著/稀有异变），用颜色和边框区分 |
| 实时预览 | 黑魂/艾尔登法环 | 选择参数时实时预览功法效果（左侧预览栏升级为实时 AI 详解） |
| 功法对比 | — | 多选功法对比属性差异 |
| 功法卡牌化 | 卡牌游戏 | 功法详情做成卡牌样式，更有收藏感和展示感 |

### 10.5 大纲与场景脚本

#### 竞品一览

| 竞品类型 | 代表产品 | 大纲特点 |
|----------|----------|---------|
| 编剧软件 | Final Draft、Fade In | 场景卡+索引卡+节拍表 |
| 思维导图 | XMind、MindManager | 树状结构+节点拖拽+折叠 |
| 故事结构工具 | Plottr、Dramatica | 故事节拍+人物弧线+时间线 |
| 看板工具 | Trello、Notion | 看板视图+拖拽+标签 |
| 写作工具 | Scrivener、壹写作 | 大纲+文档一体化 |

#### 竞品优点

| 产品 | 优点 |
|------|------|
| **Final Draft** | 场景卡（Index Card）视图经典；拖拽排序直观；节拍表（Beat Sheet）结构化 |
| **XMind** | 树状结构清晰；节点拖拽灵活；支持多种视图（思维导图/逻辑图/组织结构图） |
| **Plottr** | 专门为小说设计；故事节拍模板丰富；人物弧线可视化；时间线视图 |
| **Trello/Notion** | 看板视图灵活；拖拽体验好；标签和筛选强大 |
| **Scrivener** | 大纲和正文一体化；软木塞视图（索引卡）；支持拆分视图 |

#### 我们的现状

- 两个 Tab：卷大纲 / 场景脚本
- 场景脚本三栏：左侧素材池 / 中间场景画布 / 右侧校验侧栏
- 场景节点可拖拽排序
- 素材拖拽到场景节点
- AI 生成场景节点
- 对话式修改场景
- 智能匹配素材（扫描文本→语义召回）
- 一致性校验 8 维（时间线/地点/结构节奏/人物出场/战斗/故事引擎相关性/场景有效性/节奏健康度）
- 校验结果三色分级，点击定位到对应节点
- 缺少多种视图（列表/卡片/时间线/节奏曲线）
- 缺少故事节拍/三幕式结构模板
- 节点间关系无显式可视化连线

#### 我们的差异化优势

| 优势 | 说明 |
|------|------|
| **8 维一致性校验** | 竞品只有简单的结构检查，我们有 8 维一致性校验——时间线、地点、人物出场、节奏等都能自动检查 |
| **智能匹配素材** | 竞品的素材需要手动关联，我们能扫描场景文本，自动从知识库中语义召回相关素材 |
| **世界观数据驱动** | 竞品的大纲是"纯文本"，我们的大纲是"结构化数据+世界观联动"——场景里的人物/地点/功法都跟世界观数据库关联 |
| **AI 对话式编辑** | 竞品的场景编辑是手动改，我们可以对话式增/改/删/重排 |

#### 可借鉴点

| 借鉴点 | 来源 | 具体做法 |
|--------|------|----------|
| 多种视图切换 | Plottr、Scrivener | 列表视图 / 卡片视图 / 时间线视图 / 节奏曲线视图 |
| 故事节拍模板 | Plottr、Final Draft | 三幕式/英雄之旅/救猫咪 等经典故事结构模板，一键套用 |
| 人物弧线 | Plottr | 每个人物的弧线可视化，跟场景节点对应 |
| 看板视图 | Trello | 场景节点按状态分组（待写/写作中/已完成/需修改） |
| 节奏曲线 | — | 可视化展示整卷的节奏变化（紧张/舒缓/高潮） |

### 10.6 生成控制台

#### 竞品一览

| 竞品类型 | 代表产品 | 生成特点 |
|----------|----------|---------|
| AI 绘画 | Midjourney、Stable Diffusion | 生成过程可视化+进度条+参数展示 |
| AI 编程 | Cursor、Windsurf | AI 编程过程透明+可干预 |
| AI 写作 | NovelAI、Claude、ChatGPT | 纯文本生成，参数少，过程不透明 |
| 游戏加载 | 各类游戏 | 进度条+阶段提示+小提示 |

#### 竞品优点

| 产品 | 优点 |
|------|------|
| **Midjourney** | 生成过程可视化（从模糊到清晰）；参数丰富且直观；历史记录方便对比 |
| **Stable Diffusion WebUI** | 参数极其丰富（高级模式/简单模式）；实时预览；历史版本对比；插件生态 |
| **Cursor/Windsurf** | AI 编程过程透明（能看到 AI 在想什么）；可中途干预；diff 预览 |
| **游戏加载界面** | 进度条清晰；阶段提示明确；等待时显示小技巧/设定，不无聊 |

#### 我们的现状

- 三栏布局：左章节列表 / 中预览 / 右参数+队列+日志
- 生成参数 4 个：目标字数/温度/自动修订/文风档位
- POV/方向/出场人物/必含伏笔等从 chapter_plan 读取，不在面板暴露
- 生成中预览区显示内容，非真流式（1s 轮询，整段下发）
- 按阶段（phase）展示状态，不以 Agent 名逐步展示
- "生成日志"名不副实，实际是章节计划
- 队列状态可见，管理能力有限
- 单章生成丢弃三个参数（bug）
- 无生成前预览确认、无生成历史版本对比、无生成报告
- 缺少队列管理（暂停/取消/调整顺序）

#### 我们的差异化优势

| 优势 | 说明 |
|------|------|
| **多 Agent 管线** | 竞品是"一次性生成"，我们是"ContextComposer → Writer → Auditor → Reviser"四步管线，质量更高 |
| **世界观数据注入** | 竞品生成是"凭空写"，我们生成时自动注入世界观数据（人物设定/功法/地点等），保证一致性 |
| **章节计划驱动** | 竞品生成是"给个 prompt 就写"，我们有详细的章节计划（POV/方向/出场人物/伏笔/必须事件），生成更可控 |
| **质量审计闭环** | 竞品生成完就完了，我们生成后自动跑 27 维质量审计，不达标自动回炉重写 |
| **文风引擎控制** | 竞品只能调"温度"，我们有 8 模块结构化文风控制（心智模型/描写比例/核心意象/禁用词等） |

#### 可借鉴点

| 借鉴点 | 来源 | 具体做法 |
|--------|------|----------|
| 生成过程可视化 | Midjourney | 展示每一步 Agent 的输出（上下文构建→初稿生成→质量审计→自动修订） |

| **因果链 + 伏笔双系统** | 竞品只有一种"线索"概念，我们区分了"伏笔"（作者埋的钩子）和"因果链"（事件之间的因果关系），概念更清晰 |

#### 我们的差异化优势

| 优势 | 说明 |
|------|------|
| **叙事方向概念独特** | 竞品的内容统计是"主题/标签"统计，我们是"叙事方向"统计——战斗/情感/成长/阴谋等 10 大类 41 个细分方向，这是专门为小说设计的分类体系 |

| **LLM + 关键词双轨打标** | 竞品一般只有一种打标方式，我们是 LLM 打标+关键词兜底，准确率和覆盖率都有保障 |

### 10.14 素材知识库

#### 竞品一览

| 竞品类型 | 代表产品 | 知识库特点 |
|----------|----------|-----------|
| AI 知识库 | Notion AI、Obsidian + 插件 | 知识库+问答+生成 |
| 本地知识库 | Obsidian、Logseq | 本地知识库+双向链接+搜索 |
| RAG 产品 | LangChain、LlamaIndex | 文档上传+向量检索+问答 |

#### 竞品优点

| 产品 | 优点 |
|------|------|
| **Notion AI** | 知识库和 AI 生成深度融合；问答体验好；跟笔记功能联动 |
| **Obsidian** | 本地优先；双向链接体验好；插件生态丰富；数据完全可控 |
| **RAG 产品** | 向量检索专业；支持多种文档格式；检索效果好；可定制化程度高 |

#### 我们的现状

- 三个 Tab：文风预设 / 领域知识 / 蒸馏任务
- 5 类知识：术语/规则/坑点/表达/案例
- 搜索框支持检索（向量/关键词）
- 仅软删除，无编辑
- 3 种 ETL：style（文风）/ domain（领域）/ material（素材）
- 抓取链接填 URL 或路径（支持目录递归）
- dry-run：只解析不写入
- 启动任务触发 Python 旁路 ETL 服务
- Python 旁路服务独立：Embedding server（8600）+ GUI/ETL server（8610）
- 向量数据库：PostgreSQL + pgvector（HNSW cosine 索引）
- Embedding 模型：BAAI/bge-small-zh-v1.5，512 维
- 文档切分：Chunking 2000 字符/overlap 200
- 检索策略：纯向量检索（最低分 0.35），无混合检索/重排序
- 和生成管线自动召回联动
- 支持多知识库（按知识库名区分）
- 无独立检索测试台

#### 我们的差异化优势

| 优势 | 说明 |
|------|------|
| **结构化 + 非结构化双知识库** | 竞品的知识库要么纯结构化（数据库）要么纯非结构化（向量），我们是结构化世界观数据库 + 非结构化素材知识库结合，检索更精准 |
| **5 类知识分类** | 竞品的知识库是"文档级"分类，我们是"知识功能"分类——术语/规则/坑点/表达/案例，生成时能精准召回对应类型的知识 |
| **文风知识库** | 竞品没有这个概念——我们能从样本文风中蒸馏出"文风模型"，生成时控制文风，这是 AI 写作的独特需求 |
| **与生成管线深度融合** | 竞品的知识库是"问答工具"，我们的知识库是"生成的上下文来源"——生成时自动召回相关素材，注入到 prompt 里 |
| **本地部署 + 数据可控** | 竞品很多是云端服务，我们是完全本地化部署，数据安全可控 |

#### 可借鉴点

| 借鉴点 | 来源 | 具体做法 |
|--------|------|----------|
| 检索测试台 | RAG 产品 | 独立的检索测试页面，可以测试检索效果，调整参数 |
| 混合检索 | — | 向量检索 + 关键词检索结合，提升召回率 |
| 重排序 | RAG 产品 | 检索结果重排序（Rerank），提升准确率 |
| 文档管理 | Notion | 文档上传/编辑/删除/分类，更完善的管理功能 |
| 知识库可视化 | Obsidian | 知识库的图谱视图，展示文档之间的关系 |

### 10.15 差异化定位总结

#### 三大差异化支柱

| 支柱 | 说明 | 对应模块 |
|------|------|----------|
| **叙事工程** | 不是"AI 写小说"，而是"叙事工程系统"——伏笔、因果链、时间线、状态追踪、方向均衡，这些是竞品没有的专业叙事工具 | 伏笔台账、因果链、时间线、方向统计、叙事体检 |
| **世界观驱动生成** | 不是"给 prompt 就写"，而是"世界观数据库驱动生成"——人物设定、功法、地点等结构化数据自动注入，保证一致性 | 世界观百科、素材知识库、文风引擎、生成控制台 |
| **质量防线体系** | 不是"生成完就完了"，而是"三层质检 + 自动回炉"——叙事体检（全书）+ 质量审计（单章）+ 文风校验（文风），不达标自动重写 | 叙事体检、27 维质量审计、文风校验、生成管线 |

#### 我们 vs 竞品的核心区别

| 维度 | 竞品（AI 写作工具） | 我们（指尖仙侠） |
|------|-------------------|-----------------|
| **定位** | AI 写作助手 | 叙事工程系统 |
| **核心价值** | 帮你写得更快 | 帮你写得更好、更稳、更有体系 |
| **生成方式** | 一次性生成 | 多 Agent 管线 + 质量审计 + 自动回炉 |
| **世界观** | 纯文本设定 | 结构化数据库 + 向量检索 + 自动注入 |
| **叙事控制** | 靠 prompt | 靠章节计划 + 方向 + 伏笔 + 状态追踪 |
| **质量保证** | 没有 | 三层质检体系 + 规则计算 + 可解释 |
| **目标用户** | 随便写写的人 | 认真写长篇的作者 |
| **学习成本** | 低 | 高，但收益也高 |

#### 目标用户画像

**核心用户**：认真写长篇小说的作者，尤其是仙侠/玄幻类
- 有完整的世界观设定
- 追求叙事质量和一致性
- 写长篇（几十万字以上）
- 对 AI 写作有一定了解，但不满意现有工具的质量
- 愿意花时间学习专业工具

**次要用户**：
- 跑团/桌游 DM（需要世界观和剧情管理）
- 游戏编剧（需要叙事工程工具）
- 网文作者（需要效率和质量平衡）

#### Slogan 建议

**主 Slogan**：
> **指尖仙侠 —— 你的叙事工程系统**

**副 Slogan**：
> 不是 AI 替你写，是 AI 帮你把好每一道关

**一句话价值主张**：
> 从世界观设定到章节生成，从伏笔管理到质量审计，指尖仙侠是第一个为长篇仙侠小说设计的全流程叙事工程系统。
