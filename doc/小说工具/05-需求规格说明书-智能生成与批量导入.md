## 一、需求背景

### 1.1 现状问题

当前自定义工坊（众生百态/铸器天工/道法自然）的创建流程是：

```
点击"新增" → 手动选择各项参数 → 确认生成
```

**问题**：
- 参数太多，新手不知道怎么选
- 每次都要一步步选，效率低
- 用户心里有个大概想法，但不知道对应哪些参数组合

世界观百科的问题：
- 新增实体只能一个一个加
- 如果有一大段设定文字（比如从别的地方抄来的世界观设定），需要手动拆解、逐个录入
- 工作量大，容易遗漏

### 1.2 需求目标

| 需求 | 目标 | 核心价值 |
|------|------|----------|
| 智能匹配生成 | 输入文字描述 → AI自动匹配参数 → 一键生成 | 降低门槛、提升效率 |
| 一键批量生成 | 输入大段文字 → AI自动拆解实体 → 批量入库 | 批量导入、结构化抽取 |

## 二、需求一：自定义工坊智能匹配生成

### 2.1 功能定位

**一句话**：在自定义人物/法宝/功法的创建界面，增加一个"文字描述"输入框，用户输入一段描述，AI自动匹配出最相关的参数选项，用户确认后一键生成。

### 2.2 涉及模块

| 模块 | 当前入口 | 新增功能 |
|------|----------|----------|
| 众生百态（自定义人物） | 新增人物向导 | 智能匹配参数 |
| 铸器天工（自定义法宝） | 新增法宝向导 | 智能匹配参数 |
| 道法自然（自定义功法） | 新增功法向导 | 智能匹配参数 |

### 2.3 交互流程

```
┌─────────────────────────────────────────────────────┐
│  创建功法（道法自然）                                  │
├─────────────────────────────────────────────────────┤
│                                                     │
│  ┌─────────────────────────────────────────────┐    │
│  │  💡 文字描述生成                              │    │
│  │  ┌─────────────────────────────────────────┐│    │
│  │  │ 描述你想要的功法，AI帮你匹配参数...       ││    │
│  │  │ （例：一个雷属性的爆发型功法，适合剑修）  ││    │
│  │  └─────────────────────────────────────────┘│    │
│  │              [ 智能匹配 ]                    │    │
│  └─────────────────────────────────────────────┘    │
│                                                     │
│  ── 或者手动配置 ──                                   │
│                                                     │
│  [原有三步创建向导...]                                │
│                                                     │
└─────────────────────────────────────────────────────┘
```

**详细步骤**：

| 步骤 | 用户操作 | 系统响应 |
|------|----------|----------|
| 1 | 进入创建界面 | 顶部显示"文字描述生成"输入框 |
| 2 | 在输入框中输入文字描述 | — |
| 3 | 点击"智能匹配"按钮 | 调用 AI 分析文字，匹配参数 |
| 4 | — | 显示匹配结果：各参数的推荐选项 + 匹配度 |
| 5 | 用户调整/确认参数 | — |
| 6 | 点击"生成" | 按确认后的参数生成实体 |

### 2.4 匹配结果展示

**匹配结果区域**：
- 显示各参数的推荐选项
- 每个选项标注匹配度（高/中/低 或 百分比）
- 用户可以修改不满意的参数
- 修改后可以重新匹配（可选）

**示例（功法）**：

```
📋 智能匹配结果

道则构型：
  ✅ 雷霆道则（匹配度 95%）
  ⚪ 庚金道则（匹配度 30%）
  [更改]

本源运用方向：
  ✅ 爆发型（匹配度 90%）
  ✅ 杀伐凌厉（匹配度 85%）
  [更改]

适配门槛：
  ✅ 剑修适配（匹配度 80%）
  [更改]

...

[ 重新匹配 ]  [ 确认生成 ]
```

### 2.5 功能细节

#### 2.5.1 输入框位置

- 放在创建向导的**最顶部**
- 作为"快速通道"，下面才是手动配置
- 文案提示："不知道怎么选？用文字描述一下，AI帮你匹配"

#### 2.5.2 输入内容

- 支持中文自然语言描述
- 可以是关键词、短语、句子、段落
- 长度建议：10-500 字
- 支持多行输入

#### 2.5.3 匹配范围

**功法（道法自然）**：
- 主道则
- 辅修道则
- 核心方向
- 风格类型
- 适配种族/体质
- 等所有可配置参数

**人物（众生百态）**：
- 种族
- 体质
- 性格
- 出身
- 先天禀赋
- 等所有可配置参数

**法宝（铸器天工）**：
- 品级
- 类型
- 特质方向
- 等所有可配置参数

#### 2.5.4 匹配逻辑

**优先策略**：
1. 关键词精确匹配（如"雷"→雷霆道则）
2. 语义相似匹配（如"爆发"→爆发型方向）
3. 关联推理（如"剑修"→适配庚金/雷霆等道则）

**输出格式**：
- 每个参数返回 top-N 推荐选项
- 每个选项带匹配度分数
- 按匹配度从高到低排序

#### 2.5.5 用户确认

- AI 匹配结果**不直接生成**，必须用户确认
- 用户可以修改任何参数
- 修改后可以选择"重新匹配"或"直接生成"
- 确认后走原有的生成流程

### 2.6 数据模型

无需新增表，复用现有参数体系。

新增接口：
```
POST /forge/:type/smart-match
  body: { description: string }
  response: {
    params: {
      [paramName]: [
        { value: string, label: string, score: number }
      ]
    }
  }
```

## 三、需求二：世界观一键批量生成

### 3.1 功能定位

**一句话**：在世界观百科中，用户输入一大段文字（可能包含人物、门派、地点、功法等多种实体），AI 自动拆解识别出所有实体，并按各实体表的字段结构自动生成对应实体，批量入库。

### 3.2 涉及模块

| 模块 | 当前功能 | 新增功能 |
|------|----------|----------|
| 世界观百科 | 单实体新增/编辑 | 一键批量生成 |

### 3.3 交互流程

```
┌─────────────────────────────────────────────────────┐
│  世界观百科 / 一键批量生成                             │
├─────────────────────────────────────────────────────┤
│                                                     │
│  📝 粘贴你的世界观设定文字：                           │
│  ┌─────────────────────────────────────────┐        │
│  │                                         │        │
│  │  青云门，正道三大门派之一，掌门道玄真人...  │        │
│  │  张小凡，青云门弟子，性格坚韧...          │        │
│  │  太极玄清道，青云门镇派功法...            │        │
│  │                                         │        │
│  └─────────────────────────────────────────┘        │
│                                                     │
│  实体类型：[x] 人物  [x] 门派  [x] 地点  [x] 功法    │
│          [ ] 法宝  [ ] 妖兽  [ ] 丹药灵材  [ ] 信物  │
│                                                     │
│              [ 开始拆解生成 ]                        │
│                                                     │
└─────────────────────────────────────────────────────┘
```

**详细步骤**：

| 步骤 | 用户操作 | 系统响应 |
|------|----------|----------|
| 1 | 进入"一键批量生成"页面 | 显示大文本输入框 |
| 2 | 粘贴世界观设定文字 | — |

| 5 | — | 显示拆解结果预览：按实体类型分组 |
| 6 | 用户检查/编辑/删除识别出的实体 | — |
| 7 | 点击"确认入库" | 批量创建实体 |
| 8 | — | 显示生成结果：成功/失败数量 |

**预览界面**：
- 按实体类型分组（人物/门派/地点/功法...）
- 每组显示识别出的实体列表
- 每个实体可以展开查看字段详情
- 支持编辑、删除、跳过
- 支持全选/取消全选

### 3.5 功能细节

#### 3.5.1 入口位置

- 世界观百科页面顶部增加"一键批量生成"按钮
- 或者作为独立 Tab/页面

#### 3.5.2 输入内容

- 支持大段文字（建议上限 10000 字）
- 可以是小说原文、设定文档、维基百科条目等
- 支持多种格式：纯文本、Markdown（自动去格式）

#### 3.5.3 实体类型选择

- 8 类实体可选：人物/门派/地点/功法/法宝/妖兽/丹药灵材/日常信物
- 默认全选
- 用户可以只选需要的类型

#### 3.5.4 字段映射

AI 拆解时，尽量映射到各实体表的标准字段：

**人物表字段映射**：
| 表字段 | AI 识别来源 |
|--------|-------------|
| name | 人物名字 |
| gender | 性别描述 |
| realm | 境界/修为描述 |
| identity | 身份/职位描述 |
| personality | 性格描述 |
| appearance | 外貌描述 |
| background | 背景/经历描述 |
| faction_id | 所属门派（关联门派实体） |
| location_id | 所在地（关联地点实体） |
| ... | ... |

**门派表字段映射**：
| 表字段 | AI 识别来源 |
|--------|-------------|
| name | 门派名称 |
| location_id | 所在地 |
| leader_id | 掌门/首领（关联人物） |
| influence | 势力范围/地位描述 |
| rules | 门规描述 |
| ... | ... |

**其他实体类似，尽量对齐现有表结构**

#### 3.5.5 实体关联

AI 识别时，自动建立实体之间的关联：
- 人物 → 所属门派
- 人物 → 所在地
- 功法 → 所属门派
- 功法 → 修炼者
- 法宝 → 持有者
- 等等

**关联策略**：
- 同一批次内识别的实体，自动关联
- 已存在的实体（同名匹配），自动关联
- 不确定的关联，标注"待确认"

#### 3.5.6 去重处理

- 识别出的实体与已有实体对比（名称匹配）
- 已存在的标注"已存在"，默认不重复创建
- 用户可以选择"创建副本"或"跳过"

#### 3.5.7 确认入库

- 用户确认后，批量创建实体
- 创建成功的显示绿色对勾
- 创建失败的显示红色叉号 + 错误原因
- 支持"重试失败项"

### 3.6 数据模型

新增表：`world_batch_import`（批量导入任务表）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 主键 |
| project_id | int | 项目 ID |
| book_id | int | 书籍 ID |
| source_text | text | 原始输入文本 |
| entity_types | jsonb | 选择的实体类型 |
| status | enum | pending/processing/completed/failed |
| result | jsonb | 拆解结果 |
| created_count | int | 成功创建数量 |
| failed_count | int | 失败数量 |
| created_at | timestamp | 创建时间 |
| completed_at | timestamp | 完成时间 |

新增接口：
```
POST /world/batch-import      # 创建批量导入任务
GET  /world/batch-import/:id  # 查询任务状态和结果
POST /world/batch-import/:id/confirm  # 确认入库
```

## 四、技术实现思路

### 4.1 需求一：智能匹配生成

#### 4.1.1 实现方案

**方案 A：纯 LLM 推理（推荐）**
- 把参数选项列表作为 system prompt
- 用户描述作为 user prompt
- 让 LLM 返回匹配的参数和分数
- 优点：灵活、效果好、无需额外数据
- 缺点：每次都要调用 LLM，有成本

**方案 B：向量检索 + LLM 微调**
- 把所有参数选项向量化
- 用户描述 → 向量检索匹配
- LLM 做最终排序和解释
- 优点：快、成本低
- 缺点：需要构建向量库、维护成本高

**建议**：先用方案 A 快速上线，效果好就继续用，觉得慢/贵再优化成方案 B。

#### 4.1.2 Prompt 设计（示例）

```
System:
你是一个仙侠小说设定助手。用户会输入一段功法描述，你需要从以下选项中匹配最合适的参数。

可选参数：
- 主道则：[庚金道则, 坤土道则, 雷霆道则, 冥蚀道则, 虚空道则, 岁时道则, 形质道则, 灵气道则, 神魂道则]
- 核心方向：[杀伐凌厉, 爆发绝伦, 一击制胜, 防御稳固, 持续缠斗, ...]
- 风格类型：[攻击型, 防御型, 辅助型, 控制型]
- ...

请按以下 JSON 格式返回：
{
  "mainDaoze": { "value": "雷霆道则", "score": 95, "reason": "描述中提到'雷'和'爆发'" },
  "coreDirection": [
    { "value": "爆发绝伦", "score": 90, "reason": "..." },
    { "value": "杀伐凌厉", "score": 85, "reason": "..." }
  ],
  ...
}

User:
{用户输入的描述}
```

### 4.2 需求二：一键批量生成

#### 4.2.1 实现方案

**方案：LLM 结构化抽取（推荐）**
- 把实体类型和字段定义作为 system prompt
- 用户输入的大段文字作为 user prompt
- 让 LLM 按 JSON 格式返回识别出的所有实体
- 优点：灵活、效果好、支持多种实体类型
- 缺点：长文本 token 消耗大

**优化策略**：
- 文字太长时分块处理
- 每块识别后合并去重
- 用函数调用（function calling）确保输出格式稳定

#### 4.2.2 Prompt 设计（示例）

```
System:
你是一个世界观设定提取助手。用户会输入一段小说/设定文字，你需要从中识别出所有的人物、门派、地点、功法等实体。

实体类型和字段定义：
1. 人物（character）：
   - name: 姓名
   - gender: 性别
   - identity: 身份/职位
   - personality: 性格
   - faction: 所属门派名称
   - location: 所在地名称
   - background: 背景描述

2. 门派（faction）：
   - name: 门派名称
   - location: 所在地名称
   - leader: 掌门/首领名称
   - influence: 势力/地位描述
   - ...

3. ...

请按以下 JSON 格式返回：
{
  "characters": [
    { "name": "张小凡", "gender": "男", "identity": "青云门弟子", ... }
  ],
  "factions": [
    { "name": "青云门", "location": "青云山", "leader": "道玄真人", ... }
  ],
  ...
}

注意：
- 只提取文中明确提到的信息，不要编造
- 不确定的字段留空
- 同一实体不要重复提取

User:
{用户输入的大段文字}
```

#### 4.2.3 长文本处理

**分块策略**：
- 按字数分块（如每 2000 字一块）
- 每块独立识别
- 最后合并：同名实体合并字段，去重

**合并策略**：
- 按名称匹配
- 字段互补：A 块有的字段 + B 块有的字段
- 冲突时：取更详细的描述，或标注"待确认"

### 4.3 共用组件

两个需求可以共用一些组件：

| 组件 | 用途 |
|------|------|
| LLM 调用封装 | 统一的 LLM 调用接口，支持重试、超时、降级 |
| JSON 输出校验 | 校验 LLM 返回的 JSON 格式是否正确 |
| 实体匹配/去重 | 名称匹配、相似度计算 |
| 进度展示 | 异步任务的进度展示 |

## 五、优先级与排期建议

### 5.1 优先级评估

| 需求 | 用户价值 | 实现难度 | 优先级 |
|------|----------|----------|--------|
| 需求一：智能匹配生成 | ⭐⭐⭐⭐⭐ 降低门槛、提升效率 | ⭐⭐ 中等 | **P0** |
| 需求二：一键批量生成 | ⭐⭐⭐⭐ 批量导入、节省时间 | ⭐⭐⭐ 较高 | **P1** |

### 5.2 排期建议

**第一阶段（1-2 周）：需求一 MVP**
- 先做"道法自然（功法）"的智能匹配
- 验证效果和用户体验
- 跑通技术方案

**第二阶段（1 周）：需求一扩展**
- 扩展到"众生百态（人物）"
- 扩展到"铸器天工（法宝）"
- 优化匹配效果

**第三阶段（2-3 周）：需求二 MVP**
- 做世界观一键批量生成
- 支持人物/门派/地点三类实体
- 跑通拆解→预览→入库全流程

**第四阶段（1-2 周）：需求二完善**
- 扩展到全部 8 类实体
- 优化长文本处理
- 优化关联识别

### 5.3 风险点

| 风险 | 影响 | 应对 |
|------|------|------|
| LLM 匹配效果不好 | 用户觉得不准 | 多试几种 prompt，加示例 few-shot |
| 长文本 token 消耗大 | 成本高 | 分块处理、优化 prompt 长度 |
| 实体识别准确率低 | 入库质量差 | 增加人工确认环节，不直接入库 |
| 输出格式不稳定 | 解析失败 | 用 function calling 或 JSON schema 约束 |
