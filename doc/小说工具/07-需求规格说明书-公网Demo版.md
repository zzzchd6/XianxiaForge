## 一、目标与范围

### 1.1 核心目标

**一句话**：做一个最简的公网 Demo，让访客一眼看懂"指尖仙侠是什么、能做什么"，不需要注册、不需要配置、打开就能用。

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **最简可用** | 只保留最核心的展示功能，复杂功能全砍掉 |
| **零配置** | 下载下来双击就能跑，不需要装数据库、不需要配 API |
| **版权安全** | 完全去掉诛仙相关内容，换成原创/通用仙侠设定 |
| **好部署** | Windows 服务器一键部署，不需要懂技术 |
| **演示导向** | 重点展示 UI 和产品概念，功能深度次要 |

### 1.3 不在范围内（砍掉的）

- ❌ 所有 LLM 生成功能
- ❌ 向量检索 / RAG
- ❌ Python 旁路服务（Embedding/ETL）
- ❌ 多 Agent 生成管线
- ❌ 复杂的叙事工程功能
- ❌ 用户系统 / 登录注册
- ❌ 项目管理（单项目即可）

## 四、LLM 功能替换方案

### 4.1 替换原则

所有需要 LLM 的地方，都改成**预制数据 + 模拟过程**：
- 点击"生成" → 显示加载动画 → 显示预制结果
- 看起来像是 AI 生成的，实际上是提前准备好的
- 目的是展示产品概念，不是真的要生成

### 4.2 各模块替换方案

| 模块 | 原 LLM 功能 | Demo 替换方案 |
|------|-------------|---------------|
| **生成控制台** | WriterAgent 生成章节 | 点击生成 → 等待 3 秒 → 显示预制章节内容 |
| | Auditor 审计 | 生成完成后自动显示预制审计结果 |
| | 分支生成 | 生成完成后显示预制分支选项 |
| **章节修订** | AI 修订 | 选中文字 → 输入指令 → 等待 2 秒 → 显示预制修订结果 |
| | 视角重写 | 同上，显示预制的不同视角版本 |
| **世界观** | 深度蒸馏 | 显示预制的人物内核/功法内核 |
| **伏笔** | 自动识别 | 状态变化是手动/预制的，不做自动识别 |
| **自定义工坊** | AI 生成详解 | 选择参数 → 点击生成 → 显示预制的功法/人物/法宝详情 |
| | 千人千面变种 | 显示预制的 2-3 个变种示例 |
| **大纲** | AI 生成大纲 | 点击生成 → 显示预制的大纲 |
| | 智能匹配素材 | 显示预制的匹配结果 |
| **叙事体检** | 实时计算 | 显示预制的固定分数 |
| **金句库** | 自动提取 | 金句是预制好的 |
| **热点嗅探** | 抓取榜单 | 整个模块砍掉 |
| **素材知识库** | 向量检索 | 整个模块砍掉 |

### 4.3 模拟效果要求

- 要有**加载动画/进度条**，让用户感觉"正在生成"
- 等待时间 2-5 秒，不能太快（太假）也不能太慢（等不及）
- 结果要跟参数有一定关联（选了不同参数，显示不同预制结果）
- 可以只有 2-3 套预制数据，不用太多

## 五、数据库方案（SQLite）

### 5.1 为什么用 SQLite

| 原因 | 说明 |
|------|------|
| **零配置** | 不需要安装数据库服务，一个文件就是数据库 |
| **好部署** | 跟着程序一起走，拷贝过去就能用 |
| **够用** | Demo 数据量小，SQLite 完全够用 |
| **Windows 友好** | 原生支持，不需要额外装东西 |

### 5.2 数据库结构

**简化原则**：
- 保留核心表，砍掉不常用的表
- 每张表只保留核心字段
- 去掉复杂的关联表，能用 JSON 就用 JSON

**保留的表（建议 15-20 张）**：

| 表名 | 用途 | 数据量 |
|------|------|--------|
| book | 书籍 | 1 条（Demo 只有一本书） |
| character | 人物 | 5 条 |
| faction | 门派 | 3 条 |
| location | 地点 | 5 条 |
| technique | 功法 | 5 条 |
| artifact | 法宝 | 5 条 |
| monster | 妖兽 | 3 条 |

**砍掉的表**：
- 向量相关的表

- 热点嗅探相关的表
- 生成队列表（改成模拟）
- 复杂的审计日志表
- 等等...

### 5.3 数据初始化

- 提供一个 `init_demo_data.sql` 文件
- 里面包含所有表的创建语句和预制数据
- 程序启动时自动检测，如果数据库不存在就自动初始化
- 或者提供一个"重置数据"按钮，一键恢复初始状态

## 六、Windows 一键部署方案

### 6.1 部署目标

**一句话**：下载一个压缩包，解压后双击 `启动.bat`，浏览器自动打开，就能用了。

### 6.2 部署包结构

```
指尖仙侠-Demo/
├── 启动.bat          # 双击启动
├── 停止.bat          # 双击停止
├── README.txt        # 说明文档
├── backend/          # 后端程序
│   ├── server.exe    # 后端服务（打包后的 exe）
│   └── ...
├── frontend/         # 前端静态文件
│   ├── index.html
│   └── ...
├── data/             # 数据文件
│   └── demo.db       # SQLite 数据库
└── logs/             # 日志目录
```

### 6.3 技术方案

**后端打包**：
- 用 Node.js 的 `pkg` 或 `nexe` 把后端打包成 exe
- 或者用 Deno 打包
- 目标：单个 exe 文件，不需要装 Node.js

**前端**：
- 构建成静态文件（HTML/CSS/JS）
- 由后端服务直接提供静态文件访问
- 不需要单独的前端服务器

**数据库**：
- SQLite 数据库文件跟着部署包一起
- 不需要安装数据库服务

**端口**：
- 默认用 3000 或 8080 端口
- 启动后自动打开浏览器访问 `http://localhost:3000`

### 6.4 启动脚本（启动.bat）

```batch
@echo off
chcp 65001 >nul
echo ========================================
echo    指尖仙侠 Demo 启动中...
echo ========================================
echo.

cd /d "%~dp0"

start "" "http://localhost:3000"

backend\server.exe

pause
```

### 6.5 停止脚本（停止.bat）

```batch
@echo off
chcp 65001 >nul
echo 正在停止指尖仙侠 Demo...
taskkill /f /im server.exe
echo 已停止
pause
```

### 6.6 公网部署

**Windows 服务器部署**：
1. 把压缩包上传到服务器
2. 解压到任意目录
3. 双击 `启动.bat`
4. 配置防火墙开放对应端口
5. 用域名或 IP 访问

**可选：做成 Windows 服务**
- 用 nssm 把后端程序注册成 Windows 服务
- 开机自动启动
- 适合长期运行的公网 Demo

### 10.1 版权风险

| 风险 | 等级 | 应对 |
