## 模块一：侧边栏/信息架构

### 代码确认事实

- 侧边栏共 **16 项**，完全平铺，无分组、无二级菜单（App.tsx L42-59 navItems数组）
- 16 项：仪表盘 / 众生百态 / 铸器天工 / 道法自然 / 世界观 / 大纲 / 生成 / 章节 / 叙事线索 / 时间线 / 金句库 / 叙事体检 / 方向统计 / 热点嗅探 / 素材知识库 / 设置
- "众生百态""铸器天工""道法自然"是**一级菜单本身**（自定义人物/法宝/功法），不是分组标题
- 排序是硬编码书写顺序，无动态排序逻辑
- 无全局搜索/Cmd+K、无最近访问、无快捷键、无主题切换
- 顶部"双库状态"是**连接状态文字**（连通/断开），不是进度条【纠偏】
- 右上角"全书"是卷筛选下拉框（Select），默认'all'

---

### 第一层：UI/UX 表层问题

#### 1.1 信息架构混乱
**问题描述**：
- 16 个菜单项完全平铺，没有任何分组或层级
- 用户一眼望去全是菜单项，找不到自己要的功能
- 新用户学习成本极高

**具体表现**：
- 菜单项平铺，没有分组、没有折叠、没有分隔线
- 顺序不符合创作工作流（三个自定义模块放在世界观前面，逻辑反了）
- 质量防线模块散落各处（叙事体检/金句库/方向统计），不成体系

#### 1.2 命名风格不统一
**问题描述**：
- 三种命名风格混用：
  - 文艺仙侠风：众生百态、铸器天工、道法自然
  - 直白功能风：世界观、大纲、生成、章节
  - 混合风：叙事体检、方向统计、热点嗅探
- 用户看不懂每个菜单大概是什么功能

**影响**：
- 用户需要记住每个名字对应的实际功能
- 增加认知负担

#### 1.3 缺少快速导航
**问题描述**：
- 没有全局搜索/快速跳转（Cmd+K）
- 没有最近访问/常用功能
- 菜单多了之后找功能很慢

#### 1.4 仙侠氛围不足
**问题描述**：
- 侧边栏就是普通的后台管理系统风格
- 没有仙侠元素、没有仪式感
- 和"指尖仙侠"的产品定位不匹配

---

### 第二层：功能完整性问题

#### 2.1 缺少全局待办中心
**问题描述**：
- 伏笔超期、待审计章节、生成失败任务等提醒分散在各模块
- 没有统一的待办/通知中心
- 用户需要挨个模块去看有没有待处理的事

#### 2.2 缺少全局搜索
**问题描述**：
- 不能跨模块搜索人物、功法、章节、伏笔等
- 找东西需要先进入对应模块，再搜索

#### 2.3 缺少自定义工作区
**问题描述**：
- 所有用户看到的菜单都一样
- 不能自定义常用功能、隐藏不常用的
- 不同创作阶段的用户需求不同

---

### 第三层：数据模型与关系问题

#### 3.1 模块间数据联动不清晰
**问题描述**：
- 16 个模块之间的数据关系用户感知不到
- 比如：世界观的数据怎么影响生成？伏笔怎么和章节联动？
- 用户不知道改了一个地方会影响哪些地方

### 小结

侧边栏是整个系统的门面，当前最大的问题是**信息架构混乱**——16个模块平铺，没有分组，命名不统一，顺序不符合工作流。这会导致用户找不到功能、记不住位置、学习成本极高。

**核心结论**：P0必须做菜单分组+排序+命名优化，P1加快速跳转和待办中心，P2考虑自定义和仙侠化。

## 模块二：仪表盘/首页

### 代码确认事实

- 实际 **6 个卡片**：双库状态 / 创作热力图 / 伏笔回收进度 / 方向均衡度 / 我的项目 / 最近生成任务
- ⚠️ **纠偏**：之前推测的"剧情发展进度""活动中维度"不存在；"活动中维度"实为"方向均衡度"卡片
- 创作热力图是**相对分级**（按当前最大值比例映射），不是固定阈值
- 热力图只有 hover tooltip，不能点击下钻
- "我的项目"可点击切换 project_id
- 无全书概览关键指标卡（总字数/总章节/出场人物/伏笔数/质量评分）
- 无生成队列状态卡、无聚合待办入口
- ⚠️ **纠偏**：顶部"双库状态"是连接状态文字，不是进度条

---

### 第一层：UI/UX 表层问题

#### 1.1 定位错误：数据展示板 vs 驾驶舱
**问题描述**：
- 现在的仪表盘是"数据展示板"，展示一些统计数据
- 但用户需要的是"驾驶舱"——进来就知道该做什么，一键开始工作

**具体表现**：
- 最大的面积给了创作热力图，但热力图价值最低
- 没有"下一步该做什么"的引导
- 没有快速操作入口

#### 1.2 信息密度太低
**问题描述**：
- 页面大量空白
- 6个卡片散落在页面上，每个卡片内容很少
- 一屏看不完关键信息

#### 1.3 统计数字缺少标签
**问题描述**：
- 双库状态指示意义不明，用户不知道"连通"代表什么
- "方向均衡度"是什么意思？用户看不懂
- "伏笔回收进度"是按什么算的？

#### 1.4 视觉一致性差
**问题描述**：
- 卡片大小不一，排列不整齐
- 颜色使用不统一
- 字体大小层级不清晰

---

## 模块三：世界观百科

### 代码确认事实

- 顶部 BookSwitcher（书籍切换，默认 bookId=1）+ 数据总览 chips
- 8 类实体切换 chips：人物/门派/地点/功法/法宝/妖兽/丹药灵材/日常信物
- 列表是卡片网格
- ⚠️ **纠偏**：搜索有 bug：后端 world.ts L414 返回对象，前端 L1451 用 Array.isArray() 判断 → 渲染为空
- 人物详情三 Tab：设定/关系/深度蒸馏（写作画像）
- ⚠️ **纠偏**："深度蒸馏"是产品化命名，实质是 LLM 蒸馏的写作画像，但名字偏技术化
- 写作画像直接 JSON.stringify 原始输出，无可视化
- 人物关系只有列表，无关系图谱；诛仙库关系是 relType 自由文本 + interactCount 互动次数，无亲密度字段；自定义人物关系才有 relLevel（1-5 数值）
- 人物详情无出场章节列表
- 人物状态时间线在"时间线"模块，不在世界观里
- ⚠️ **纠偏**：WorldBrowser 只展示诛仙库实体，自定义人物在"众生百态"模块，分开的
- 功法详情两 Tab：设定/蒸馏；功法招式结构化，独立表 technique_move
- 宗门规制/岁时节令/文风引擎是世界观内的分区/子模块
- 文风引擎 8 模块：心智模型/决策启发式/描写比例/核心意象/禁用词/视角规则/反模式/场景文风映射
- ⚠️ **纠偏**：文风引擎是书籍级（bookId），但生成时硬编码 bookId=1（context-builder.ts L195）
- 文风引擎和生成自动联动
- 实体编辑是弹窗表单；乐观锁 version+1 用户看不到；软删除不能恢复，无回收站

### 第一层：UI/UX 表层问题

#### 1.1 搜索功能不可用
**问题描述**：
- 全局搜索有 bug，完全不可用
- 925 篇功法、数百个人物，没有搜索根本找不到

**影响**：
- 世界观是产品核心卖点之一，搜索坏了 = 世界观模块废了一半
- 用户找实体要翻页，效率极低

#### 1.2 写作画像展示粗糙
**问题描述**：
- "深度蒸馏"（写作画像）直接 JSON.stringify 原始输出
- 没有任何结构化可视化
- 用户看到一大段 JSON 文本，体验极差

**影响**：
- 写作画像是世界观模块的核心亮点之一
- 展示方式完全是开发者视角，用户看不懂
- 功能做了但用户感知不到价值

#### 1.3 命名技术化
**问题描述**：
- "深度蒸馏"这个名字太技术化
- 用户不知道是什么意思
- 应该叫"道心""人物内核""心智画像"等更仙侠/更通俗的名字

#### 1.4 诛仙库和自定义实体割裂
**问题描述**：
- WorldBrowser 只展示诛仙库实体
- 自定义人物在"众生百态"、自定义功法在"道法自然"、自定义法宝在"铸器天工"
- 用户要在 4 个地方分别看不同的实体

**影响**：
- 用户体验割裂
- 同一个"世界观"被拆成了 4 个模块
- 用户找实体要来回切换

### 第二层：功能完整性问题

#### 2.1 缺少人物关系图谱
**问题描述**：
- 人物关系只有列表，没有图谱视图
- 人物关系网络不直观

#### 2.2 缺少出场章节列表
**问题描述**：
- 人物详情没有"出场章节"列表
- 用户想知道"这个人在哪几章出现过"，要去章节里翻

#### 2.3 缺少人物状态时间线
**问题描述**：
- 人物状态时间线在"时间线"模块，不在人物详情里
- 用户看人物详情时看不到状态变化

#### 2.4 功法分类太粗
**问题描述**：
- 功法只有单级标签
- 925 篇功法找起来痛苦
- 缺少多级分类、筛选、排序

#### 2.5 缺少实体双向链接
**问题描述**：
- 实体之间缺少双向链接
- 比如看功法详情，不能直接跳转到修炼这个功法的人物
- 看人物详情，不能直接跳转到他的门派

#### 2.6 软删除不能恢复
**问题描述**：

## 模块五：大纲与场景脚本

### 代码确认事实

- 两个 Tab（卷大纲/场景脚本）共享同一份 outlines 数据，是同一数据的两种视图
- 场景脚本三栏：左侧素材池（220px，8 类素材含伏笔）/ 中间场景画布 / 右侧校验侧栏（300px，条件显示，触发校验后才出现）

- 场景节点能拖拽排序
- "AI 生成"生成场景节点（非卷大纲）

## 模块八：叙事线索（伏笔+因果链）

### 代码确认事实

- 两个独立实体/两张表：foreshadow_thread（伏笔）与 causal_chain（因果链），不是同一东西的两视图
- 伏笔台账顶部 **8 个统计数字**：总数/待埋/已埋/已收/废弃/超期/分支衍生/待回填
- 状态筛选：全部/待埋入/已埋设/已回收/已废弃（status 4 态+全部）
- 伏笔卡片：名称 + 标签（优先级/类型 tier 3 级） + 描述 + 操作按钮
- 卡片右下角小图标按钮：编辑/回填/状态流转等
- "回填埋设"有两种模式：
  - anchor（写入 must_have_events）
  - revise（LCS diff，红绿差异预览）→ 确认保存为新版本
- 伏笔编辑弹窗完整字段：名称/描述/埋设线索关键词/状态/优先级/埋设章节/回收章节/关联场景节点 ID/绑定伏笔手法/DNA 四元组/tier/sourceType
- "埋设线索关键词"用于自动识别：正文出现 hint_clue→状态流转为 planted
- 关键词匹配基于关键词匹配（state/store.ts L251-293），非语义级，存在误判可能
- "关联场景节点 ID"字段偏技术
- "绑定伏笔手法"支持语义召回推荐
- DNA 四元组（主体/动作/客体/情绪）存于伏笔记录
- 因果链独立页面（CausalChainPage），列表+顶部统计
- 因果链 5 个状态：planted/foreshadowed/triggered/resolved/expired
- 因果链和伏笔概念相近易混（产品设计问题）

### 小结

素材知识库的架构设计很好（Python 旁路服务、解耦、降级方便），但 UI 太技术化，非技术背景的用户上手困难。纯向量检索也有局限。检索测试台的缺失让用户无法评估和调试检索效果。

**核心结论**：P1命名通俗化+空状态引导+检索测试台；P1加文档管理+混合检索+联动说明；P2做检索效果评估和智能切分。
