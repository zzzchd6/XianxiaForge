## 一、全局与信息架构

### 1.1 侧边栏菜单

**G-001 侧边栏到底有多少个菜单项？完整列表？**
共 **16 项**，定义在 `packages/web/src/App.tsx` L42-59 的 `navItems` 数组：仪表盘 / 众生百态 / 铸器天工 / 道法自然 / 世界观 / 大纲 / 生成 / 章节 / 叙事线索 / 时间线 / 金句库 / 叙事体检 / 方向统计 / 热点嗅探 / 素材知识库 / 设置。
⚠️ 纠偏：功能手册说"25个模块"指的是后端功能模块数，不是侧边栏菜单数；菜单就是 16 个一级入口，没有折叠。

**G-002 菜单分组逻辑？平铺还是分组？**
**完全平铺**，无分组、无二级菜单。`navItems` 是一维数组，渲染时逐项 map（`App.tsx` 侧边栏 `<nav>` 区域）。

**G-003 "众生百态""铸器天工""道法自然"是一级菜单还是分组标题？**
是**一级菜单本身**，分别对应自定义人物、自定义法宝、自定义功法三个模块。不是分组标题。

**G-004 菜单排序规则？为什么"铸器天工"在"世界观"前？**
排序就是 `navItems` 数组的**硬编码书写顺序**，无动态排序逻辑。当前顺序把三个自定义模块（众生百态/铸器天工/道法自然）放在世界观之前，属于产品设计决定，代码层无"为什么"的依据。

**G-005 有没有全局搜索/快速跳转（Cmd+K）？**
**没有。** 全代码无 Cmd+K / 命令面板实现。各模块内部有各自的搜索框（如世界观、金句库无、素材库有），但无全局跳转。

**G-006 有没有"最近访问"/"常用功能"？**
**没有。** 无访问历史记录机制。

**G-007 顶部"双库状态指示"显示什么？**
显示两个数据库的**连接状态文字**（连通/断开），不是进度条。见 `Dashboard.tsx` L196-220（双库状态卡片，渲染连接状态文本）。
⚠️ 纠偏：清单推测"顶部两条进度条"不准确——那是仪表盘里的"双库状态"卡片，内容是连接状态而非进度。

**G-008 右上角"全书"按钮是干嘛的？**
是**卷筛选下拉框（Select）**，默认值 `'all'`（全书），可切换到具体某一卷。见 `DirectionStats.tsx` L44-56。不是普通按钮，是筛选器。

### 1.2 全局交互

**G-009 深色/浅色主题切换？**
**没有。** 深色主题（黑金云纹设计系统）硬编码在 `tailwind.config.js` 与 `index.css`，无切换开关。

章节用**多行版本链**（version/parentVersionId/isCurrent）；其他实体多为 **upsert + version+1** 乐观锁，非完整版本历史。

**DA-007 统一机制还是各自做？**
**各自实现**，不统一（章节版本链 vs 实体乐观锁）。

### 15.4 性能与扩展

**DA-012 书长了哪些查询变慢？**
无 GIN 索引的 jsonb 过滤、全书全量重算（叙事体检）、伏笔/状态全表扫描等会随章数增长变慢。

**DA-013 生成队列并发？默认1？可配？**

**DA-014 大表分页？**
**offset 分页**（非游标）。

**DA-015 有缓存吗？**

### 15.5 降级与容错

**DA-016 "降级红线"实现？每增强点try/catch？**
是，增强点用 **best-effort try/catch** 独立包裹，失败不阻断主流程。

**DA-017 LLM调用失败重试策略？**
LLM client `maxRetries:0`（不内置重试）；**队列层指数退避 30s/120s/480s，最多 3 次**。

**DA-018 向量服务宕机哪些降级？**
向量召回**降级为空**（empty recall）；固定素材（pinned）不受影响仍工作。

**DA-019 降级用户能感知吗？**
**多为静默降级**（仅 `console.warn`），用户不易察觉（体验隐患）。
