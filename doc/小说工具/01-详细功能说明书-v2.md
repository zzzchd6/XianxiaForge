## 一、产品概览

### 1.1 一句话定位

**指尖仙侠是一个本地化部署的 AI 长篇小说创作工具，以结构化世界观数据库为知识源，通过多 Agent 管线自动生成符合设定的小说章节，并提供完整的叙事工程与质量防线体系。**

### 1.2 核心能力

| 能力维度 | 说明 |
|----------|------|
| **结构化世界观** | 诛仙小说 18 表结构化数据库 + pgvector 512 维向量，支持语义检索 |
| **多 Agent 生成管线** | ContextComposer → Writer → Auditor → Reviser，4 步流水线 |
| **叙事工程体系** | 伏笔台账 + 因果链 + 时间线 + 方向统计 + 影响体系 + 状态追踪 |
| **质量防线** | 27 维剧情审计 + 8 维文风校验 + 9 维叙事体检 + 去 AI 味检测 |
| **自定义工坊** | 自定义人物/功法/法宝，支持千人千面变种系统 |
| **降级红线架构** | 所有增强点 best-effort，失败不阻断主流程 |

### 1.3 技术栈

| 层级 | 技术 |
|------|------|
| **前端** | React 19 + TypeScript + Tailwind CSS + @dnd-kit |
| **后端** | Hono + TypeScript + Drizzle ORM |
| **数据库** | PostgreSQL + pgvector（HNSW cosine 索引） |
| **向量模型** | BAAI/bge-small-zh-v1.5，512 维 |
| **Python 旁路** | Embedding server（8600）+ ETL/GUI server（8610） |
| **包管理** | pnpm monorepo |
| **部署方式** | 本地化部署，支持 Windows/macOS/Linux |

### 1.5 双库架构

产品采用**双数据库**设计：

| 数据库 | 用途 | 表数量 | 连接池 |
|--------|------|--------|--------|
| **novel_db**（诛仙库） | 诛仙小说结构化数据，作为世界观知识源 | 18 张 | max 5 |
| **novel_studio**（创作库） | 用户创作数据、项目、章节、伏笔等 | 40+ 张 | max 10 |

**关键设计**：
- 自定义实体使用**负数 ID**，与诛仙库正数 ID 共存分流
- 诛仙库非严格只读，存在写入操作（如蒸馏结果）
- 两库独立连接池，无数据库级外键关联
- 应用层通过 project_id 实现项目隔离

**我的理解**：

- 质量防线模块散落各处（叙事体检/金句库/方向统计），不成体系
- 缺少全局搜索（Cmd+K）、最近访问、快捷键等高效导航方式

### 2.2 顶部栏

**顶部栏元素**：
- 左侧：Logo + 产品名
- 中部：双库状态指示（诛仙库/创作库 连接状态）
- 右侧：卷筛选下拉框（默认"全书"）

**代码确认事实**：
- "双库状态"是**连接状态文字**（连通/断开），不是进度条
- 右上角"全书"是卷筛选 Select，默认 `all`

### 2.3 仪表盘 / 首页

![仪表盘](dashboard.png)

**代码确认事实**：
- 实际 **6 个卡片**：双库状态 / 创作热力图 / 伏笔回收进度 / 方向均衡度 / 我的项目 / 最近生成任务
- 创作热力图是**相对分级**（按当前最大值比例映射），不是固定阈值
- 热力图只有 hover tooltip，**不能点击下钻**
- "我的项目"可点击切换 project_id

**6 个卡片详情**：

| 卡片 | 内容 | 数据来源 |
|------|------|----------|
| 双库状态 | 诛仙库/创作库连接状态 | 数据库连接池 |
| 创作热力图 | 类 GitHub 贡献图，按日字数渲染 | 创作统计表 |
| 伏笔回收进度 | 已回收/总数 + 超期数量 | 伏笔台账 |
| 方向均衡度 | 均衡度评分 + 占比最高大类 | 方向统计 |
| 我的项目 | 项目列表，点击切换 | 项目表 |
| 最近生成任务 | 近期任务状态/耗时/tokens | 生成队列表 |

**我的理解**：
- 仪表盘定位有问题：是"数据展示板"而不是"驾驶舱+行动入口"
- 最大面积给了创作热力图，但热力图价值最低（不能下钻、相对分级无绝对意义）
- 缺少全书概览关键指标（总字数/总章节/出场人物/伏笔数/质量评分）
- 缺少待办提醒聚合（伏笔到期、生成失败、待审计等）
- 缺少快速操作入口（新建章节、开始生成、跑体检等）

## 三、世界观与设定

### 3.1 世界观百科

![世界观百科1](worldview1.png)

**代码确认事实**：
- 前端入口：`/world`（`WorldBrowser.tsx`，1541 行，全内联）

#### 3.1.1 8 类实体

顶部 8 个实体切换 chips：

| 序号 | 实体类型 | 说明 | CRUD |
|------|----------|------|------|
| 1 | 人物 | 角色设定 | ✅ 新增/编辑/软删除 |
| 2 | 门派 | 宗门设定 | ✅ |
| 3 | 地点 | 地理设定 | ✅ |
| 4 | 功法 | 功法设定 | ✅ |
| 5 | 法宝 | 法宝设定 | ✅ |
| 6 | 妖兽 | 妖兽设定 | ✅ |
| 7 | 丹药灵材 | 丹药和灵材 | ✅ |
| 8 | 日常信物 | 日常物品和信物 | ✅ |

列表展示形式：**卡片网格**

#### 3.1.2 全局搜索

**⚠️ 已知 bug**：
- 后端 `world.ts` L414 返回**对象**格式
- 前端 `WorldBrowser.tsx` L1451 用 `Array.isArray()` 判断
- 判断失败 → 渲染为空 → 搜索完全不可用
- 影响：925 篇功法、数百个人物，没有搜索根本找不到

#### 3.1.3 人物详情

![世界观百科2](worldview2.png)

人物详情 **3 个 Tab**：

| Tab | 内容 | 说明 |
|-----|------|------|
| **设定** | 基本设定 | 姓名、性别、境界、身份、性格、外貌、背景... |
| **关系** | 人物关系 | 关系类型、对方人物、关系描述、互动次数 |
| **深度蒸馏** | AI 提炼的人物内核 | 心智模型、决策启发式、人生阶段 |

**关于"深度蒸馏"**：
- 这是产品化命名，实质是 LLM 蒸馏的**写作画像**
- 当前展示方式：直接 `JSON.stringify` 原始输出，**无可视化**
- 用户看到一大段 JSON 文本，体验极差
- 建议改名："道心"或"人物内核"（更仙侠、更通俗）

**人物关系数据模型**：
- 诛仙库关系：`relType` 自由文本 + `interactCount` 互动次数
- **无亲密度字段**（自定义人物关系才有 `relLevel` 1-5 数值）
- 只有列表，**无关系图谱**

**我的理解**：
- 写作画像是世界观模块的核心亮点之一，但展示方式完全是开发者视角，用户感知不到价值
- 人物关系只有列表没有图谱，浪费了关系数据的价值
- 缺少出场章节列表（用户想知道"这个人在哪几章出现过"要去章节里翻）
- 人物状态时间线在"时间线"模块，不在人物详情里，体验割裂

#### 3.1.4 功法详情

功法详情 **2 个 Tab**：

| Tab | 内容 |
|-----|------|
| **设定** | 基本设定：名称、品阶、属性、修炼条件、功效... |
| **蒸馏** | AI 提炼的功法内核：属性分析、招式列表、关系网络 |

**功法招式**：
- 诛仙库功法招式用独立表 `technique_move`
- 结构化存储，不是 JSON

#### 3.1.5 文风引擎

文风引擎是世界观内的子模块，共 **8 个模块**：

| 模块 | 说明 |
|------|------|
| 心智模型 | 叙事视角和思维方式 |
| 决策启发式 | 角色决策模式 |
| 描写比例 | 各类描写的占比（环境/心理/动作/对话） |
| 核心意象 | 常用意象和象征 |
| 禁用词 | 禁止使用的词汇 |
| 视角规则 | 叙事视角规则（POV 规则、视角切换规则） |
| 反模式 | 避免的写作模式 |
| 场景文风映射 | 不同场景的文风预设 |

**代码确认事实**：
- 文风引擎是**书籍级**（bookId）
- ⚠️ 但生成时硬编码 `bookId=1`（`context-builder.ts` L195）
- 文风引擎和生成自动联动

#### 3.1.6 其他子模块

| 子模块 | 说明 |
|--------|------|
| 宗门规制区 | 宗门规章制度列表，支持 CRUD |
| 岁时节令区 | 岁时节令列表，支持 CRUD |

#### 3.1.7 实体编辑

- 编辑方式：弹窗表单
- 乐观锁：`version+1`（用户看不到）
- 软删除：不能恢复，**无回收站**

### 3.2 自定义人物（众生百态）

**代码确认事实**：
- 独立模块，不在 WorldBrowser 里
- 自定义人物使用**负数 ID**，与诛仙库正数 ID 共存分流
- 人物关系有 `relLevel`（1-5 数值），诛仙库没有
- 先天禀赋：4 大类 166 条正向 + 23 条小缺陷

**我的理解**：
- 诛仙库和自定义实体完全分开，用户体验割裂
- 同一个"世界观"被拆成了 4 个模块（世界观/众生百态/铸器天工/道法自然）
- 用户找实体要来回切换

### 3.3 自定义功法坊（道法自然）

**代码确认事实**：
- 前端入口：`CustomTechniqueForge.tsx`，1130 行，全内联
- 列表是卡片网格，无筛选排序，无搜索框，无批量操作

#### 3.3.1 功法卡片

卡片显示信息：
- 功法名字
- 道则标签
- 深度徽标（传承深度三档之一）
- 攻击方向 chips

#### 3.3.2 功法详情

**⚠️ 重要纠偏**：详情弹窗**根本没有 Tab**！

之前以为有 4 个 Tab，实际是：
- "入门指引" = `guidanceDepth`（传承深度）徽标三档之一：入门指引/完整传承/直指本源
- "杀伐凌厉/爆发绝伦/一击制胜" = 攻击型 `styleType` 的 3 个 `coreDirection`（核心方向）chips
- 详情是**单个可滚动 Dialog**，由多个 DetailBlock 顺序铺陈

**详情 Dialog 字段块（按顺序）**：

| 序号 | 字段块 | 说明 |
|------|--------|------|
| 1 | 道则构型 | 主道则 + 辅修道则 |
| 2 | 本源运用方向 | 核心方向 + 风格类型 |
| 3 | 适配门槛 | 修炼条件 |
| 4 | 分道境神通 | 各境界的神通 |
| 5 | 典型运用技巧 | 常用技巧 |
| 6 | 反噬代价 | 修炼反噬 |
| 7 | 演化方向 | 功法演化路径 |
| 8 | 身体印记 | 修炼后身体变化 |
| 9 | 功法详解 | 纯文本段落 |

#### 3.3.3 千人千面·变种系统

**核心亮点功能**：
- 基于**四因子**确定性推导：主道则 × 种族 × 性格 × 出身
- 每次选择不同因子，产生不同变种
- 变种稀有度徽标：common=普通 / remarkable=显著 / rare=稀有异变

**数据模型亮点**：
- 变种差异存储（`offsets`），只存相对原功法的偏移量
- 不存完整副本，节省空间
- 原功法修改后，变种自动更新
- **这个设计非常聪明**

#### 3.3.4 配套招式

- 存 `moves` jsonb（自定义功法）
- 默认 4 招
- 诛仙库功法招式用独立 `technique_move` 表
- 两套设计不统一

#### 3.3.5 创建向导

**三步创建向导**：

| 步骤 | 名称 | 内容 |
|------|------|------|
| 1 | 道则构型 | 选择主道则 + 辅修道则 |
| 2 | 行功根骨 | 选择种族 + 体质 + 性格 |
| 3 | 衍化配置 | 配置演化方向 + 神通 |

**左侧预览栏**：
- 显示当前配置汇总
- **非实时 AI 详解**（只是回显字段）
- 信息密度较低

**其他功能**：
- "一键全随机"按钮：按兼容矩阵随机配比（高/中/冲约 60:35:5）
- 道则选择有对冲警告（冲突标红）
- 步骤条是常规样式，仙侠风主要在配色纹饰

#### 3.3.6 数据模型

**大量 JSON 字段**：
- 辅修道则、核心方向、典型技巧、适配门槛等全部 jsonb
- 无中间表
- 查询筛选性能差

**功法和人物关联**：
- 用 `linked_character_ids` jsonb 数组
- 无中间表
- 查询"某个人物修炼了哪些功法"需要全表扫描

### 3.4 自定义法宝（铸器天工）

根据功能手册：
- 品级六阶 × 三层
- 方向组合式特质（4 类 × 4 维度 × 56 方向）
- 五感兵器卡
- 成长工坊系统

### 4.2 卷大纲

### 4.3 场景脚本

![场景脚本1](scene_script1.png)

**三栏布局**：

| 区域 | 宽度 | 内容 |

#### 4.3.1 场景节点

**场景节点（scene_node）**：

- 支持拖拽排序（@dnd-kit）

**场景节点编辑字段**：

| 分组 | 字段 | 说明 |

## 十、数据架构

### 10.1 双库架构

| 数据库 | 用途 | 表数量 | 连接池 |
|--------|------|--------|--------|
| novel_db（诛仙库） | 诛仙小说结构化数据 | 18 张 | max 5 |
| novel_studio（创作库） | 用户创作数据 | 40+ 张 | max 10 |

**关键设计**：
- 自定义实体使用负数 ID
- 两库独立连接池
- 无数据库级外键
- 应用层 project_id 隔离

### 10.2 JSON 字段统计

- 创作库约 **100 个 jsonb** 字段
- 诛仙库 17 个
- 仅素材清洗库表建了 GIN 索引
- 其余 jsonb 多无索引

**性能隐患**：
- 无 GIN 索引的 jsonb 过滤
- 全书全量重算（叙事体检）
- 伏笔/状态全表扫描

### 10.3 版本管理

- 章节：多行版本链（version/parentVersionId/isCurrent）
- 其他实体：upsert + version+1 乐观锁
- 各自实现，不统一
- 版本存全量快照（非 diff）

### 10.4 队列实现

- DB 即队列 + 轮询
- 无独立消息队列
- 指数退避重试（30s/120s/480s，最多 3 次）
- 默认并发 1

### 10.5 降级红线

**架构原则**：
- 所有增强点用 best-effort try/catch 独立包裹
- 失败不阻断主流程
- 降级多为静默降级（仅 console.warn）
- 用户不易察觉（体验隐患）

**降级场景**：
- 向量服务宕机 → 向量召回降级为空
- 固定素材（pinned）不受影响
- LLM 调用失败 → 队列层重试
