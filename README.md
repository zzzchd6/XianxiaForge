## 🤔 这不是又一个"套壳 ChatGPT 写小说"

市面上的 AI 写作工具大多是：**前端输入框 + 后端调 API + 返回一段文字**。于是你会遇到：

| 😫 痛点 | ✨ XianxiaForge 怎么做的 |
|----------|---------------------------|
| 写到第 80 章忘了第 3 章的设定，人设漂了 | **30 维剧情审计** 每章自动审查人设/境界/关系是否漂移，未通过触发回炉修订 |
| 埋了 20 个伏笔收到第 5 个就忘了 | **伏笔台账** 追踪每条伏笔从埋设→回收的完整生命周期，超期标红催债 |
| AI 写的像 ChatGPT 作文，一眼机翻 | **8 型 AI 味分型** + **零 token 本地扫描**（禁用词/套话腔/排比堆砌），定向改写 |
| 剧情分支选了就忘了，后面圆不回来 | **影响体系** 量化每个分支选项的数值变化 + **因果链** 追踪长期后果 |
| LLM 把筑基期写成能秒元婴，战力崩了 | **确定性规则兜底**：品阶上限、互斥校验、稀有度约束 —— 全部代码把关，LLM 只管"写"，不管"守规矩" |

### 三个核心理念把这套工具和其他所有 AI 写作方案区别开

```
┌──────────────────────────────────────────────────────┐
│                                                      │
│   ✦ 作者主权 ✦         你是导演，AI 是制片助理        │
│   每段 AI 输出必经人工预览→确认→入库                  │
│   每次修改生成新版本，永不覆盖原文，可回退              │
│                                                      │
│   ✦ 确定性兜底 ✦      100% 关键约束零 token 执行      │
│   品阶数学 · 互斥校验 · 禁用词扫描 · 时间线校验        │
│   全部由纯函数把关 → 零 token 成本 · 零误判 · 零幻觉  │
│                                                      │
│   ✦ 降级红线 ✦        LLM 宕了，正文照常出            │
│   向量服务挂了？AI 味扫描炸了？静默降级为空             │
│   绝不因任何 AI 辅助功能失败阻断正文生成               │
│                                                      │
└──────────────────────────────────────────────────────┘
```

> 🎯 **一句话说清定位**：这不是"更好的 AI 提示词工程"，而是一个 **会自己运行的世界模拟器**。你在这个世界里导演故事，AI 是帮你布景、打光、校对台词的那个助理。

## ✨ 功能特色

### 🎬 五步写作流水线

```
章节计划 ──→ 上下文编排(20+项上下文) ──→ Writer 写作 ──→ 本地预校验
                                                    │
    ┌── 通过 ──→ 精修压缩 ──→ 保存正文 ──→ 后置处理链 ────┐
    │                                          ├ 状态抽取    │
    ▼                                          ├ 伏笔流转    │
Auditor 30维审计                                ├ 分支生成    │
    │                                          ├ 金句管线    │
    └── 未通过 ──→ Reviser 六层回炉 ──────────→┘ 实体维护    │
```

- **SSE 流式推送**：编排→写作→审计→修订→完成，全程实时可见
- **DB 任务队列**：任务持久化 PostgreSQL，原子认领，服务重启不丢
- **主备模型自动切换**：首选 LLM 宕机 → 秒切备用 → 写作者无感
- **回炉温度变化**：初次 0.7 → 一次修订后 0.8 → 二次修订后 0.9（越改越大胆）

### 🌳 交互式剧情分支

每一章写完后，AI 不是"猜你想写什么"——而是在完整世界观约束下，**推演合理的剧情走向选项**：

```
"前往后山禁地探查？"          → 分支A（奇遇方向）  → 影响: 修为+1 风险+3
"留在门派应对内乱？"          → 分支B（阵营方向）  → 影响: 声望+3 忠诚+2
"追随神秘老者的指引离去？"    → 分支C（探索方向）  → 影响: 气运+2 羁绊+1
```

- 每个选项附带 **影响预览**（人物数值/世界状态量化变化）
- 选定后自动 **衍生下一章计划** + 抽取伏笔 + 埋设因果线
- 分支上下文 **沿链路累积**，保证多章走向一致
- **分支弧硬限**：5 章自动收敛回主线，防止失控

## 🚀 快速开始

### 前置要求

- **Node.js** ≥ 20 LTS
- **pnpm** ≥ 9
- **PostgreSQL** ≥ 15（含 pgvector 扩展）
- 仙侠世界数据库（world_db）已导入

### 安装

```bash
# 1. 克隆项目
git clone <your-repo-url>
cd novel-studio

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env → 填入数据库连接 + LLM API Key

# 3. 一键启动（Windows）
start.bat
# 自动完成：检查环境 → 安装依赖 → 初始化DB → 启动前后端 → 打开浏览器

# 或手动启动
pnpm install
pnpm dev
```

启动后访问 **http://localhost:5173** 🎉

### 配置 LLM

支持任意 **OpenAI-compatible** 接口：

| 提供商 | `.env` 配置 |
|--------|-------------|
| DeepSeek | `LLM_BASE_URL=https://api.deepseek.com` `LLM_MODEL=deepseek-chat` |
| OpenAI | `LLM_BASE_URL=https://api.openai.com/v1` `LLM_MODEL=gpt-4o` |
| 本地 Ollama | `LLM_BASE_URL=http://localhost:11434/v1` `LLM_MODEL=qwen2.5` |
